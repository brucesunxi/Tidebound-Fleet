# I5-C3 经济模型

本目录是离线研发工具，不被玩家构建引用，不读取／修改玩家存档，不接广告、支付或排行榜。`simulate_economy.py`已从旧I5-B单抽模型升级；旧结果保留在Git及I5-B验证记录，不能直接把两个版本的差异解释为仅由价格变化造成。

## 运行

在Unity工程目录执行：

```sh
python3 -m unittest discover -s Tools/Economy -p test_economy.py -v
python3 Tools/Economy/simulate_economy.py --players 1000 --suite full --out /tmp/EconomyScenarios.json
```

模拟和测试只有Python标准库依赖；可选的`plot_report.py`需要Matplotlib和含中文字体，用于重绘报告PNG／SVG，不进入运行时依赖。`--suite pilot --players 100`用于快速比较32个主方案；full增加装备、兑换、广告／两种礼包、重开、扩池、船数及章节券的单因素敏感情景，共55个方案。默认seed20260920，每方案1000人，每人假定最终完成300关，共1650万个模型关卡回合。输出在3／10／30／100／300关记录P10／中位／P90；首次抽取／首次十连／集齐另外报告达成人群比例，未发生事件不以0混入中位数。

## 生产对照

`production_contract.json`由Unity菜单 **Tools → Tidebound → Export Economy Model Contract** 导出。批处理入口为`Tidebound.EditorTools.EconomyContractExport.Export`，可用`TIDEBOUND_ECONOMY_CONTRACT`指定输出路径。只需导出生产契约，不会加载玩家存档。

契约包含：真实目录／上限／转券／兑换价、生产价格与首通、商店配置、实际10关标准／长船数、金币概率、工具额度和赠送参数；另用8个固定合成档案执行520笔真实C#抽取／十连／兑换事务并逐笔校验档案。Python模拟必须逐字段复现结果、钱包成本、券、拥有和全部保底计数。

生产源文件或关卡文件hash变化时，模型停止并要求重新导出，不静默使用旧参数。候选价格不写入生产契约；曲线放在`CURVES`，玩家行为放在`POLICIES`，完整假设随JSON保存。

## 与旧模型的区别

- 单抽／十连各自按生产随机流运行，十连起始U锁价、批内保底和重复转换；兑换发生在批次之后，当前关号达到5才开放。
- 第2关结算后当前关号变成3，免费蓝皮后即可金币单抽；不是等第3关结束才开放。
- 道具类型库存分开保存，读取250／300／200单价及650组合包，入场赠送，跨关保留，成功使用才消耗；按已结算钱包购买，无法用未结算战斗金币购买。
- 不固定35%／65%预算：模拟即时收藏、预留650金币、攒十连、预留1500金币四种明确行为。生产游戏没有这些预算限制。
- 玩家可选择五款高品质、单独最喜欢的高品质皮肤或只用默认船。模型的装备策略是外生假设，不代表游戏自动装备。
- 前10关读取真实船数；第11关以后重复2～10关的船数构成作为工作量假设，没有生成新关卡。按attempt序号轮换多出的船数；战斗金币用与生产公式等价的分组二项分布，未逐船重放SHA奖励种子。
- 广告／礼包／扩池／章节券／额外失败attempt均单独标记为假设情景。常规比较中均未开启。

## 指标解释

`skins`含免费蓝皮和兑换，不含默认船；`pool`为该时点非默认内容数。`unfunded`是可用额度内的“希望使用但无相应库存／金币”，不是失败关数；`over_limit`是超出每attempt5次额度的愿望量，单列且不能通过购买解除。`coverage`是该人群的实际使用次数／额度内请求数。模型假设道具都有合法目标，不模拟解题、脱困率、放弃或留存。

`max_draw_gap`含尚未满足的当前等待，仅在有未拥有内容时累计；扩池前已集齐期间不算钱包导致的等待。`first_complete`是首次集齐当时已发布池的关号，扩池后`complete`会重新变为false，不等于已经集齐未来内容。

现实每天完成关数、道具需求、真实广告填充、礼包购买、装备偏好、重开和弃游行为均未观测。输出用于挑选下一轮测试参数，不能宣称平衡、留存、收入或真机体验通过。C3候选尚未激活；采用时必须另建规则版本并保护旧凭证与活动attempt。
