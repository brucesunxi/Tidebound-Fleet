# 完全死局提示与长期关卡衔接修订

日期：2026-09-20。依据用户最新竞品死局截图与“第十关结束也不要直接返回主页，后续几百关”的要求。以下覆盖旧的自动死局弹窗、十关终点与返回主页主按钮方案。

## 完全死局只提示

- 沿用严格判定：所有剩余船都无法前进或驶出，移动、航道与攻击队列结束后才提示；没有直出船但能部分前进不算完全死局。Solver 的 Unknown 不能触发。
- 在局内显示短提示“船只都堵住了，试试道具吧”，轻提示一个有库存且本局仍可使用的道具。提示不遮罩整屏、不截获触控、不暂停，不要求点击关闭。
- 优先展示玩家可执行的动作。库存不足提示可回主页补给；5次用尽提示可从菜单重开。购买库存不能增加本次使用次数。
- 不自动打开道具选择页／商店、不自动消耗、不替玩家选择目标、不自动重开。菜单和现有道具按钮仍由玩家操作。
- 同一盘面状态只做一次显眼提示；文字短暂显示后淡出、指引随后收起，具体时长是待验证参数。盘面变化后重新评估，后台／暂停不累计动画。减少动态时仅静态文字或边框。
- 5秒无操作提示继续只找当前能直接驶出的船；无直出船就不提示。它与死局提示是两条独立规则。

可点击稿的完全死局样例已换成六船循环紧邻阻挡，用文字条和道具边框展示位置，不打开模态框；这里静态保留提示供评审，不表示正式提示应永久停留。真实时序在 Unity 接入时验证。

## 第十关是普通关卡

| 状态 | 结算动作与数据行为 |
|---|---|
| 第10关通关，目录存在第11关 | 与其他关相同，显示奖励及下一奖励目标；玩家点“下一关”后进入第11关 |
| 当前安装内容暂到第10关 | 保留成功结算、主页与分享；点下一关显示“第11关尚未开放，通关奖励已保存”，留在结算，不新建attempt、不重复奖励 |
| 关卡继续扩到几百关 | 使用稳定关卡ID、序号和内容可用状态，不以`level == 10`决定导航，不循环回第1关 |
| 已完成当前内容后主动回主页 | 主按钮查看原通关结算；不宣称“全部游戏完成”，不创建虚假下一关 |

返回主页始终由玩家选择。奖励展示仍等待最后航道、攻击和可靠保存；分享不加未经确认的金币，也不成为下一关条件。奖励节点数量和关卡总数解耦，后续只展示邻近已得／下一目标节点，不把几百个节点挤在同一页。

## 现有工程边界与后续顺序

- Unity `VictoryResult.HasNext` 已使用发布数量与当前关号比较，包含10→20的既有测试；本轮增加目录数量500时第10关仍有下一关的回归案例。
- **当前 `CandidateLevelCatalog` 是十关候选的严格审计目录，确实要求10组关卡与证明。** 不直接删除该校验来假装支持量产；V2-C1抽取正式关卡目录接口和可用性判断，保留候选审计用于研发。未来生产目录按稳定ID加载当前关与必要预载，不在启动时加载／求解数百关。
- **本轮死局与按钮流程改动在可点击稿中；Unity E1仍使用旧模态死局界面，正式导航、提示条和内容边界反馈列入V2-C1接入。** 没有生成第11关或500个真实关卡，没有改变真实存档／道具／奖励事务。
- B1船体样片继续；B2将这一提示条与结果状态加入版式；C1实现导航及非模态死局提示；D1／D2让真实奖励目录与结算同源；实际关卡扩充仍在设备门槛之后分批开展。

## 预览检查

独立Chrome检查360×640、390×844、430×932，以及浅／深外观，共6组：死局无模态、底部道具可点击、暂停返回后提示保持、结算停留、分享返回，以及第10关在后续已配置的演示状态进入第11关。脚本无运行异常。演示“后续已配置”只有流程数据，局内仍用既有静态布局，不能当作第11关内容已制作。

Unity针对结果投影的EditMode测试 **10/10通过**，包括目录数量500的第10关HasNext=true；见[结果XML](../../验证记录/V2_流程修订/ResultEditMode.xml)。这验证结算投影能力，不代表严格十关候选目录已改成生产目录。
