# Phase 5R I1：反向生成与动态求解验收

日期：2026-09-19。阶段结论：I1算法检查点通过；I2十关、真实竖屏场景、真人和Android验收尚未完成，不进入战斗。

## 已实现

- `LevelSolver.cs` 成为统一入口。先尝试真实直出剥离；N艘以N步清空即达到下界。失败则从原始状态做包含部分前进的BFS，用规范完整状态键去重、父节点还原最短解。
- 区分 `Invalid / Solved / Deadlocked / LimitReached`；状态数量、保留的占格数量、时间分别受限。硬锁证据或完备搜索才返回Deadlocked，预算耗尽不冒充无解。
- 完整阻挡图继续扫描到边界，对一艘长船去重；保留最近阻挡和移动距离供反馈。旧 `DependencyDepth` 仍是历史首阻挡边数，新 `CompleteDependencyDepth` 用完整图的节点数，含环时为null；每次从当前Board重新分析。
- `ReverseLevelGenerator.cs` 从空棋盘与四边出口出发；每艘新插入船必须自身出口全空，可挡住既有船；限制独立种子、初始出口、完整链深、方向比例／熵及相邻同向率。固定PRNG只用于合法候选排序；有界分支回溯，不够船或不达门槛只返回失败，不偷偷减数量或改长度。
- 复用已有Board事务、移动、航道、JSON加载；旧有界搜索入口转调新Solver，避免维护两套搜索逻辑。没有改回“受阻原地”或“碰撞退回”。
- 新增版本化证明伴随文件及JSON适配，记录规则／出口版本、SHA-256布局指纹、每步起终点／结果／前后指纹。布局仍是schema v2；旧12样本及旧FNV证明保留历史回归，不自动升级为新证明。

Unity 2022.3.25f1，本机macOS。两次最终命令均退出0，最终运行日志无C#编译错误。

本次增加34个EditMode测试用例，重点包括：

1. 四方向运行时“先前进两格停住→紧邻零位移→移走阻挡再前进→最终离场”，提交前旧占格保持、提交后不退回。
2. 多个完整路径阻挡与长船去重；部分前进新增另一艘船的阻挡，旧快照不变。
3. 四船开局无出口的可解环，BFS求得5步最短解，同船可以重复出现在序列；有可移动动作但最终必卡死的对冲样本通过穷尽状态判无解。
4. 闭合零位移环、状态／占格预算、无效规则／出口／数据、空棋盘、规范键以及证明篡改／过期／不完整负例。
5. 7／80船逐个重建插入前缀，检查当时新船确实可直出；相同seed重复生成得到一致布局、证明及指标；失败不返回半关。
6. 落盘7／80船从JSON重载，独立求解后通过 `ShipMovementSystem.CompleteTravel` 提交，再由 `TransitSystem.Advance` 入舰：棋盘清空、航道清空、每船出场与入舰各一次且FIFO一致。

第6项是EditMode中的真实逻辑模型集成，完成回调和时钟由测试推进；没有把它写成真实点击、动画场景或手机测试。PlayMode仍是已有6项表现回归。

## 源码借鉴与边界

按照[源码借鉴表](../../SOURCE_REUSE_MATRIX.md)的S01复用已验证的移动行为与事务；S16的缺口在Tidebound纯逻辑层原创实现。未导入外部原始脚本、美术、停车运动或广告SDK。

当前结构门槛证明“初始存在无道具解”，并不证明任意玩家操作后仍有解；生成也不保证每个seed在预算内成功。存储占格预算是搜索内存规模的保守控制量，不是实测MB；时间限制是协作式检查，不是硬实时保证。

I1重点验证算法与契约。80船样本仍有局部平行排列，方向熵／相邻同向率不能代替视觉和触控验收；I2应增加长同向行列、局部方向混合、空间空洞及前中后期解锁节奏筛选，再决定保留或重新生成样关。不得把本样本直接冻结为产品第2关。
