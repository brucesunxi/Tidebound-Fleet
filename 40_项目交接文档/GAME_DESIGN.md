# Tidebound Fleet（潮汐舰队）游戏设计文档

**版本：1.1｜日期：2026-09-18｜阶段：产品规则基线／Phase 1 基础建设**

**一句话定义：**玩家点击具有固定朝向的船，疏通海面船阵；每艘成功驶出的船沿边缘航道加入舰队，自动攻击海怪一次，连续出船带来不断增强的炮击反馈。

目标为竖屏、单指操作的原创移动解谜游戏，平台为 Android／iOS，发行渠道包括 Google Play／TapTap。核心玩法可离线完成。

本文件基于[《源码资产评估报告》](源码资产评估报告.md)和用户提供的五张方向／船型参考图编写。v1.0 为只读设计交付；v1.1 记录用户确认的 Phase 1 数据与工程边界。本文规定的 MVP 玩法“验收”仍是后续开发完成时要达到的标准，不表示玩法已经实现或测试通过。

## 本版已确定的关键规则

| 事项 | v1.0 定义 |
|---|---|
| 方向 | 仅上、下、左、右；普通点击不能自行选择方向 |
| 受阻 | 尽可能前进，到阻挡前停住；绝不退回原位置 |
| 占格 | 船体覆盖全部格子；第一版宽度统一 1 格，长度分 2／3／4 格 |
| 出场与入战 | 船尾完全离开棋盘才算驶出；抵达战区才算加入舰队 |
| 攻击 | 方案 A：每艘船入战触发一次攻击；没有周期自动射击 |
| 同型船 | 每个船型只保留一个战区展示实体；累计数量和待攻击次数分别记录 |
| 连击 | 任意船型连续驶出都可续接；5 秒窗口，仅提升特效、音效与轻震动 |
| Boss | 一个海怪，不主动攻击；MVP 的总血量等于本关 Lv.1 船只总伤害 |
| 胜利 | 棋盘清空、航道清空、攻击全部命中、Boss 血量为 0 后统一结算 |
| 移除道具 | 救援拖离选中的船，仍加入舰队并攻击一次 |
| 失败与付费 | 无限时、无步数和生命限制；卡局可用道具或免费重试，不要求看广告才能通关 |
| MVP | 4 船型、1 Boss、12 个原创关卡、3 道具、连击、首通金币与本地进度 |

本阶段采用最新要求中的“持续驶出船提升攻击特效”：**不同船型也延续连击**。此前概念中的“必须连续相同船型才升级特效”不作为 MVP 限制。同型合并展示继续保留，船型不会相互合成为新船型。

规则与初始数值分开管理：方向、一次入场一次攻击、受阻不回退等为固定规则；伤害、动画时长、连击阈值等为本版明确采用的初始调优值，调整须同步本文和验收预期。

# 1. 游戏核心循环

## 1.1 玩家一次游戏的完整流程

1. **进入关卡。** 读取原创船阵、船型、方向和海怪血量；显示剩余船数、道具数量。MVP 不需要登录，不消耗体力。
2. **观察船阵。** 通过尖船头、宽船尾和船头单向标记，判断哪些船能直接出海、哪些船需要先让路。
3. **点击船只。** 船沿固定方向移动；无遮挡则驶出，有障碍则前进到障碍前停止。玩家观察新的空间关系，再做下一次选择。
4. **船进入航道。** 船尾离开棋盘后，缩成航道船影，沿外围流向上方中央入口；剩余船数减少，连击条刷新。
5. **加入舰队。** 首艘同型船建立战区席位；后续同型船融入已有席位，累计数量加 1，待攻击次数加 1。
6. **自动攻击海怪。** 对应船型发出一次攻击；命中扣血，呈现本次出船所获得的连击表现等级。
7. **继续疏通。** 棋盘操作与上方攻击并行。玩家不需要在两个区域之间反复切换操作模式。
8. **获得奖励。** 最后一艘船入战、最后一次攻击命中后击败海怪；播放结算，发放首通金币，解锁下一关。

主循环为：**观察 → 点击 → 疏通 → 出海 → 融入 → 炮击 → 再观察**。一次完整关卡结束后进入“结算 → 下一关／重玩／返回”的外层循环。

## 1.2 玩家 30 秒内理解的核心乐趣

玩家需要形成一句话理解：**“先让能走的船出去，腾出空间；船出去越连贯，上面打海怪就越爽。”**

| 首次体验时间 | 玩家经历 | 需要理解的事情 |
|---|---|---|
| 0–5 秒 | 出现 3 艘快艇，一艘高亮，船头方向明确 | 点船即可操作，朝向决定移动方向 |
| 5–12 秒 | 第一次出船，航道尾迹引导视线，快艇炮击，Boss 扣血 | 解谜动作直接变成战斗反馈 |
| 12–22 秒 | 第一艘船腾出通路，玩家继续点击其他船 | 观察阻挡关系，选择出船顺序 |
| 22–30 秒 | 3 连击出现增强炮击，Boss 被击败，结算金币 | 连续疏通有节奏反馈，一局有明确成果 |

第 1 关目标是让首次玩家在 30 秒左右完成，不用复杂弹窗讲规则。只允许短提示“点击船只，沿船头方向驶出”。第 2 关再安排一次受阻停船教学，不在第一屏同时介绍三个道具。

## 1.3 玩法定位与结束条件

- **主要挑战：**识别船头、规划解除阻挡的顺序、理解移动后新的占位。
- **主要爽感：**棋盘逐渐变空、船只连续汇入、同型舰队叠加、炮击升级和海怪受击。
- **战斗定位：**MVP 的海战是解谜进展的可见反馈，不引入战斗操作、闪避或装备搭配门槛。
- **无惩罚项：**普通碰撞不扣金币、道具、血量或次数；观察时间不限。
- **卡局判定：**棋盘仍有船、没有棋盘移动进行中、所有船都无法前进至少一格且无法驶出时，判为卡局。
- **卡局响应：**一次性提示“试试调整方向或救援一艘船”，保留道具与免费重试；不会自动弹失败页，也不会自动弹广告。局面发生改变后可重新判定。
- **重试：**恢复关卡初始布局、Boss、舰队和连击；本次未结算奖励不发放。免费道具恢复到本关开局额度，广告补充另按第 9 节处理。

# 2. 屏幕布局规范

## 2.1 百分比的计算基准

所有比例基于扣除系统刘海、摄像头挖孔、状态／导航栏占用和底部手势保留区后的**游戏安全矩形 S**。记其宽为 W、高为 H，坐标原点在左上角，向下为屏幕正方向。

“航道不超过 5%”在本版解释为：**四周航道及中央入口的专用区域合计不超过 S 面积的 5%**，而非左右各占 5%，也不额外增加一个 5% 高度的横条。

| 分区 | v1.0 分配 | 坐标／边界 | 对用户限制的满足 |
|---|---:|---|---|
| 顶部战斗区 | 18% H | y = 0 至 0.18H，宽 W | 不超过 20% |
| 中部海面区，含航道 | 68% H | y = 0.18H 至 0.86H，宽 W | 航道从该区域内部划出 |
| 底部道具区 | 14% H | y = 0.86H 至 H，宽 W | 不超过 20% |
| 中部外围航道 | 合计最多约 4.45% 的 S 面积 | 中部海面区内侧等宽边框，中央入口包含在上边框内 | 不超过 5% |
| 棋盘净可用矩形 | 高至少 66.2% H，面积至少约 63.55% S | 中部去掉四周航道后的内部矩形 | 高度和面积均不少于 60% |

航道边框宽度 **t = W 的 2% 与 H 的 0.9% 中的较小值**。因此棋盘净矩形尺寸为 W−2t、0.68H−2t；航道面积为中部矩形面积减去棋盘净矩形面积。中央入口只是上边框中的通行点，不再增加额外通道面积。

在 360×640 的安全矩形示例中：战斗区高 115.2，道具区高 89.6，t=5.76；棋盘净矩形约 348.48×423.68。航道约占安全面积 3.92%，棋盘净区约占 64.08%。实际布局可向内取整，不能因像素取整突破上限。

## 2.2 分区内容与视觉优先级

- **顶部：**暂停、关卡号、金币、Boss 名称与血条、Boss 表现、最多 4 个舰队席位、连击条。Boss 与舰队通过独立纵深／视区组织，UI 不另占棋盘高度。
- **中部：**只有船阵、轻网格、水面与必要方向提示。第一版采用与屏幕上下左右对齐的棋盘，不沿用 Cocos 的 45° 棋盘旋转。
- **边缘：**非交互的细航道、流向标记、缩略船影／尾迹。全尺寸船尾驶出后平滑缩小，不要求在细航道里保持棋盘上的船体尺寸。
- **底部：**三个等宽道具入口，分别为移除船、洗牌、方向转换；显示剩余次数，0 次时显示真实可用的补充入口或缺货状态。
- **装饰：**岸线、棕榈树和云层可延伸到 S 外，但不能盖住 S 内的点击区域。炮弹、Boss 触手和爆炸都裁剪在战斗区，不能盖住船头或道具。

屏幕优先级为：**船头和阻挡关系 > 玩家操作反馈 > Boss 血量和炮击 > 环境装饰**。只有顶部战斗区有高频闪光，棋盘海面不使用强反光干扰轮廓。

## 2.3 所有 UI 的安全区域规则

| UI／交互 | 安全规范 |
|---|---|
| 顶部按钮、金币、关卡名 | 位于 S 内；距外边缘至少 8 个项目逻辑单位；不得与 Boss 血条覆盖 |
| Boss 血条与连击条 | 位于顶部 18% 内；连击条始终固定位置，不能临时向下顶开棋盘 |
| 舰队席位 | 固定按快艇、炮艇、战舰、旗舰从左到右排序；未入场席位不接受点击 |
| 道具按钮 | 每个点击区域至少 48×48 个项目逻辑单位，按钮间至少 8；整块位于底部 14% 内 |
| 船只点击 | 点击范围受该船占格约束；相邻船热区不得重叠；边界归属固定，不能一次点击选中两艘 |
| 引导手指与气泡 | 允许覆盖部分空水面；不可遮住被教的船头、可点击船体或下一步目标；普通气泡不拦截棋盘输入 |
| 暂停、重试确认、结算、广告补充面板 | 居于 S 内，宽不超过 90% W，高不超过 80% H；正文超出时内部滚动；阻止点击穿透 |
| Toast／错误提示 | 放在对应区内空位或已有面板中；不得临时占据棋盘中央、遮挡正在点击的目标 |
| 系统／广告覆盖层 | 核心游戏暂停；覆盖层返回后重新读取安全区，再恢复交互 |

“项目逻辑单位”是按目标手机显示尺度使用的 UI 排版单位，不等同于设备物理像素，也不是引用某个平台规范的名称。MVP 的普通 UI 正文不小于 14，重要数字不小于 16，道具按钮标签不小于 14。

## 2.4 设备适配与棋盘缩放

- MVP 竖屏手机验收范围为安全矩形宽至少 360、高至少 600 个项目逻辑单位；覆盖 9:16、9:19.5、9:20 手机比例。
- 棋盘使用正方形格子，完整显示，不滚动、不手势缩放。矩阵居中放入棋盘净区；少船关允许空水面，不能为了填满空间拉伸成非正方格。
- MVP 最大棋盘为 8 列×9 行；在最小验收安全矩形中，每格边长不低于 40。横向船的短边、纵向船的短边都须可点击。
- 更宽的设备使用居中的竖屏游戏框，外侧为非交互海景；百分比仍相对于该框内部安全矩形计算。平板专项布局不属于 MVP。
- 战斗区、棋盘区、道具区分开缩放；海怪放不下时缩小海怪，不能侵占棋盘净区。

# 3. 船系统设计

## 3.1 四种基础船型

尺寸均为**宽×长的逻辑占格**。竖向为 1×长度，横向旋转为长度×1；视觉高度、甲板和炮管不增加占格。方向字段允许 Up／Down／Left／Right，每个实例只取其中一个。

| 名称 | typeId | Lv.1 尺寸 | Lv.1 单次伤害 | 攻击启动最小间隔 | 最大启动频率 | 首次出现 |
|---|---|---:|---:|---:|---:|---|
| 快艇 | TF_SPEEDBOAT | 1×2 格 | 10 | 0.20 秒 | 5 次／秒 | 第 1 关 |
| 炮艇 | TF_GUNBOAT | 1×2 格 | 20 | 0.25 秒 | 4 次／秒 | 第 3 关 |
| 战舰 | TF_BATTLESHIP | 1×3 格 | 30 | 0.35 秒 | 约 2.86 次／秒 | 第 5 关 |
| 旗舰 | TF_FLAGSHIP | 1×4 格 | 50 | 0.45 秒 | 约 2.22 次／秒 | 第 7 关 |

**攻击速度只约束同型船待攻击队列的播放节奏。** 队列为空时，即使船仍显示在战区也不攻击。它不是固定 DPS，也不让一艘船随时间反复产生伤害。不同船型可同时攻击。

所有船在棋盘上使用相同移动规则和移动速度，避免玩家误把体型或船型当成移动权限差异。不同长度只改变阻挡关系和离场所需位移。

## 3.2 轮廓、头尾与参考图使用

统一为明亮卡通海战风格。每艘船的**前端收尖，后端明显加宽并具有平切／双推进器特征**。全船视觉宽度控制在所属格宽的 82% 内，首尾保留少量视觉留白，不能让贴图伸入旁船占格。

| 船型 | 第一眼识别点 | 色彩辅助 | 头尾强化 |
|---|---|---|---|
| 快艇 | 低矮流线舱、尖头、短船身 | 白＋亮蓝 | 后部宽尾板和双尾流；前甲板保持简洁 |
| 炮艇 | 中短船身、单主炮塔 | 橙黄＋深灰 | 主炮指向尖船头，船尾为宽平台 |
| 战舰 | 长船身、前后分布的双炮塔 | 海军蓝＋浅灰 | 前窄后宽；船尾双推进器固定成对出现 |
| 旗舰 | 最长船身、宽后甲板、后置指挥塔 | 深蓝＋金色 | 大尖船头、明显平切宽尾；后部塔楼与前端尖角形成反差 |

3. [大型舰船参考](</var/folders/h5/vvwnmwj95vggtb2phkzh88kw0000gn/T/codex-clipboard-5f25dcfe-14f1-4130-8179-ed6e805e770a.png>)：借鉴旗舰的长轴、后置指挥塔和宽重尾部，转化为海面舰船，简化密集细节。

参考图中的文字、水印和图案不属于产品 UI 或功能要求；本版不直接将参考照片裁成正式船资产。

每艘船船头附近显示**一个**低干扰方向三角，方向与船体朝向一致。禁止双向箭头，禁止用锚、十字、骷髅等无方向符号代替方向。颜色只辅助识别，关闭色彩后仍须能通过长度、炮塔和轮廓区分四型。

## 3.3 船实例与舰队展示

- 每艘棋盘船有独立实例身份，其船型和伤害在本次关卡开始时固定。
- 首艘某型船抵达战区，出现该型展示实体并攻击；之后同型到达只融入该实体。
- 席位的 `×N` 表示本关累计加入数量，攻击后不减少；另一个较小的“待发 N”仅在有待启动攻击时显示，启动一次减少 1。
- 入场临时船影只负责过渡，不计作第二艘常驻同型战船。
- 四型固定席位不因数量增多移动位置，不拥挤成一整排重复船。

## 3.4 升级路线与本版边界

四型都采用**同型 Lv.1 → Lv.2 → Lv.3**，不互相变换；升级不改变占格、方向或攻击次数，也不提高队列启动频率。

| 船型 | Lv.1 伤害 | Lv.2 伤害 | Lv.3 伤害 | Lv.1→2 金币 | Lv.2→3 金币 |
|---|---:|---:|---:|---:|---:|
| 快艇 | 10 | 12 | 15 | 200 | 400 |
| 炮艇 | 20 | 24 | 30 | 300 | 600 |
| 战舰 | 30 | 36 | 45 | 450 | 900 |
| 旗舰 | 50 | 60 | 75 | 600 | 1,200 |

这是后续成长版本的首轮数值方案。**MVP 只使用 Lv.1，不开放升级购买、升级界面或等级随机掉落。** 金币先积累并保存，升级功能启用时必须为后续关卡配置对应战斗规则；不能直接把 Lv.2／Lv.3 套进本版“总伤害等于 Boss 血量”的 12 关中。旧版 12 关重玩始终按 Lv.1 试炼规则计算，不随未来升级改变。

# 4. 挪船规则

## 4.1 方向与操作

- 仅允许上下左右直线移动，与屏幕方向一致。
- 一次普通点击只能使被点击船沿**当前船头方向**移动；不支持拖动、不支持斜向、不支持倒车。
- 普通点击不旋转；方向只可被方向转换或洗牌道具改变。
- 按下和抬起均落在同一艘船上才算点击；移出后抬起取消。位于 UI 上的触摸不传到棋盘。
- MVP 同一时刻只执行一艘船的棋盘移动。移动期间的额外棋盘点击不缓存、不追加执行，不消耗任何东西；移动完成后立即恢复输入。航道移动和战斗不锁棋盘。

## 4.2 占格定义

棋盘列从左至右编号 0…C−1，行从下至上编号 0…R−1。每船以**船尾格**为锚点，沿船头方向连续占据长度 L 个格子；船头是最前方占格。

例如，一艘长度 3、向右、船尾位于 (1,2) 的战舰，占据 (1,2)、(2,2)、(3,2)。判断前方阻挡从 (4,2) 开始，自己的格子不被当作障碍。

- 每个格子最多被一艘船占据；船体全部格子参与阻挡，不能只检测船头或中心点。
- 静止船完整处于棋盘内，禁止初始重叠或半船越界。
- MVP 棋盘为完整矩形，无岛礁、缺角格、传送门或特殊障碍；其他船是唯一障碍。
- 格间水面是美术留白，不是可额外穿行的半格空间。

## 4.3 无遮挡：驶出

沿当前方向扫描，若直到该边界都没有其他船占格，则点击后连续直行，直到**船尾完全越过棋盘边界**，成为一次成功驶出。

船头探出边界仍不算完成；驶出动画期间，棋盘移动锁保持，不能让另一艘船穿过仍在画面中的船尾。驶出完成时一次性移除占位、剩余船数减 1、分配出场序号、刷新连击、进入航道。

四条边都可驶出，不需要先在棋盘内部移动到上方中央入口。中央入口属于航道汇入战区的环节。

## 4.4 有阻挡：前进后停止

若前方最近障碍与船头之间有 d 个空格，则船沿方向移动 d 格，停在障碍前最后一个合法位置；接触反馈表现为轻撞音、短促震动和船体原地摆动。

- **禁止回到本次起点，更禁止回到关卡初始位置。** 新位置成为后续判断的唯一当前位置。
- 若 d=0，船保持原位，原占格完整保留，只播放轻撞反馈。
- 不推动被撞船，不造成伤害，不连续弹跳，不扣资源。
- 阻挡移动不计成功驶出，不产生攻击，不增加连击，也不立即清空已有连击；连击计时自然继续。
- 视觉摆动不得造成船体沿前进轴明显倒退，不能用“前进后退回”的 Tween 模拟碰撞。

**示例：**长度 3 的向右战舰占据列 1–3，同一行列 6 被占据。前方列 4、5 为空，战舰前进 2 格，占据列 3–5 并停住。再次点击且列 6 仍被占据时，位移为 0，占位仍为列 3–5。

## 4.5 移动与状态反馈

| 行为 | 首版表现值 | 规则影响 |
|---|---|---|
| 有效直线移动 | 参考 12 格／秒，单次时长限制 0.18–0.60 秒 | 到达终点前不接受第二次棋盘移动 |
| 零位移碰撞 | 0.12 秒原地轻摆 | 不改变占位，不退回 |
| 正常碰撞落点 | 停稳后约 0.12 秒反馈，可与解锁输入衔接 | 必须以新落点记录位置 |
| 方向转换 | 0.20 秒原地转向 | 占用原来的格子，不扫描中间旋转体积 |
| 航道转场 | 船尾离场后缩为船影 | 已出棋盘的船不能再被点击或被道具选中 |

占位改变与画面完成必须一致。暂停、切后台后恢复到同一次移动，不从起点重播，也不重新发出出场事件。

# 5. 航道系统

## 5.1 出场流程

**棋盘 → 对应边缘接入口 → 外围航道 → 顶部中央入口 → 战区对应船型席位。**

航道是自动演出区域，不可点击，没有容量上限、碰撞扣血或堵塞失败。它承担“这艘解谜船进入了战斗”的视觉因果说明。

| 离开棋盘的边 | 路线 |
|---|---|
| 上边 | 沿上边框向中央入口靠拢 |
| 左边 | 沿左航道向上，到左上角后向中央入口靠拢 |
| 右边 | 沿右航道向上，到右上角后向中央入口靠拢 |
| 下边 | 从下边接入口选路程较短的左／右边绕行上方；路程相同固定选右侧 |

左右两条向上汇流的路线在中央入口合并。船可以在航道中转弯，这不改变第 4 节的棋盘单向规则。

## 5.2 多船出场与入战顺序

- 船尾完全离场时得到递增的**出场序号**。首艘为 1，随后为 2、3……。
- 入战顺序严格采用出场序号 FIFO，后出的船不能因出口更靠近中央而先加入舰队。
- 每艘船从完全离场至中央入口的名义通行时间为 **1.20 秒**。不同路径通过演出速度补偿，转角保持平滑，不使用同一固定速度导致远路额外惩罚。
- 中央入口放行最小间隔为 **0.15 秒**。放行后统一用 0.15 秒完成抵达席位／融入表现，再记为加入舰队；不同船型不额外插入不同时长的入场。极端情况下后船在入口前等待，仍不影响棋盘出船。
- MVP 棋盘移动串行，因此通常不会真正同一时刻离场；仍可能有多艘船同时在航道中。若系统在同一更新时刻收到多个有效出场，按操作受理顺序排序，再以关卡内实例编号作为最终平局规则。
- 普通驶出与救援拖离共用同一排序规则。每个实例只领取一次序号，只加入一次舰队。

示例：A 从下边先出场，B 随后从上边出场。即使 B 的路径短，也必须 A 先入战；玩家连续出船的顺序保持可预测。

## 5.3 转场与异常边界

- 出场顺序在离开棋盘时确定；连击也在这个时刻计算，不受入口等待影响。
- 暂停冻结路径、入口队列和战斗；恢复后按剩余进度继续。
- 航道只有缩略船影和尾迹，不设置需要点击的等待按钮。
- 关卡重试时旧航道、旧攻击和旧出场事件全部失效，不能进入新的一局。
- 胜利页必须等航道清空，不能让仍在路上的船被结算页截断。

# 6. 战斗系统

## 6.1 方案 A：每船一次攻击

当一艘船通过中央入口、完成加入舰队时，对应 typeId 的待攻击队列增加 **1 次**。无待发攻击时立即启动；同型正在启动冷却内则按先进先出等待。

**N 艘船只产生 N 次攻击。** 第 3 艘同型船到达，仅新增 1 次，不是让现有 3 艘再各打 1 次；累计数量不乘算伤害，不产生永久攻速加成。

- 首艘某型船也会攻击，不需要等待第二艘。
- 快艇为单发轻炮；炮艇为一枚重炮弹；战舰为一次双炮齐射；旗舰为一次重型能量炮击。
- “一次双炮齐射”或高级粒子弹片可以有多条视觉轨迹，但整次仍只结算该船型的一份伤害。战舰 Lv.1 齐射合计为 30，不是每个炮口 30。
- 没有暴击、命中率、弹药损耗、元素克制、护甲、随机伤害或海怪回血。
- 入战和发射不是扣血时点；**命中时才扣一次血**。炮弹必定命中，表现被裁剪或降低特效也不能丢伤害。

## 6.2 攻击节奏与反馈

| 船型 | 发射至命中参考时间 | 主要反馈 |
|---|---:|---|
| 快艇 | 0.20 秒 | 清脆炮声、小水花，强调连续节奏 |
| 炮艇 | 0.25 秒 | 较厚炮声、橙色命中光 |
| 战舰 | 0.30 秒 | 双炮齐射、较宽命中波纹 |
| 旗舰 | 0.35 秒 | 重型光束／炮击、短暂 Boss 轮廓闪白 |

同型最小启动间隔按第 3 节执行。多个船型可以并行发射；同一时刻命中按计划命中时间、出场序号稳定结算。血条不会因事件顺序不稳定而回涨或重复扣血。

本次攻击使用该船**离场时记录的连击档位**。进入航道后连击断掉，也不降低已经获得的攻击表现；后续达成更高连击，也不追溯升级先前已出船的攻击。

## 6.3 战斗与解谜一致性

MVP 每船 Lv.1、每船一次固定伤害，移除道具也保留入战攻击。因此：

**本关 Boss 初始 HP = 本关全部船只的 Lv.1 伤害之和。**

例如：3 艘快艇、2 艘炮艇、1 艘战舰、1 艘旗舰，共 7 艘，Boss HP 为 3×10＋2×20＋30＋50＝150。战区常驻最多 4 个实体，整局总共攻击 7 次，累计伤害 150。

这让玩家能确定“全部船安全出海就一定能赢”，不会因选船顺序、碰撞或使用救援导致伤害不足。连击不增加伤害，通关不要求高速操作。

## 6.4 胜利与结算

同时满足以下四项才进入胜利：

1. 棋盘剩余船数为 0。
2. 航道和入战等待数为 0。
3. 所有待发及飞行中攻击均已完成。
4. Boss HP 为 0。

最后一击后播放约 1.0 秒死亡与金币聚集表现，再显示结算。下一关按钮在金币入账和进度保存后可用，不重复发放奖励。

正常 MVP 配置不会出现 Boss 先死而棋盘还有船，也不会在所有攻击结束后 Boss 仍存活。若发生此情况，属于配置／重复事件错误，不能向玩家要求额外广告或购买伤害；停止正常结算，提供恢复／重试，并作为必须修复的验收失败。

棋盘已清空但炮弹还在飞时显示“舰队正在完成攻击”，正常等待，不判失败。

# 7. 连击、成长与奖励节奏

本节补齐任务清单中未列出的第 7 章，集中定义连击条和局外成长边界。

## 7.1 连击计时进度条

- 第一艘船成功离开棋盘时，连击数设为 1，进度条从满开始倒计时 **5.0 秒**。
- 下一艘船在 5.0 秒内或恰好到达边界时成功驶出，连击数加 1，计时重新设为 5.0 秒。
- 连击适用于所有船型。碰撞、方向转换、洗牌和观看广告本身不增加连击；救援拖离完成算一次出船，可以延续。
- 超时后连击数清零，进度条淡出；下次出船从 1 开始。超时不扣血、不扣钱、不减少已经生成的攻击。
- 判断依据是船尾完全离场的时刻，而不是点击时刻。玩家在最后一瞬点击但船尚未出界，不能提前刷新。
- 同一更新时间发生出船与到期时，先按事件时间比较；恰好等于 5.0 秒的出船续接，超过才重置。

| 连击数 | 攻击表现档位 | 本次攻击变化 | 伤害变化 |
|---|---|---|---|
| 1–2 | I 基础 | 标准炮弹和命中 | 无 |
| 3–5 | II 连射热身 | 炮弹拖尾增强、命中亮度提升、短提示 | 无 |
| 6–9 | III 火力升温 | 双层尾迹、命中环和更厚音效 | 无 |
| 10 及以上 | IV 舰队齐鸣 | 船型专属强化炮击、战区内短促震动 | 无 |

10 次以上计数继续增长，但视觉档位封顶；不无限增加粒子、闪光或音量。连击升级不改变发射次数，也不使其他舰队席位无成本额外攻击。

## 7.2 暂停、观察与连击公平性

- 暂停菜单、系统中断、后台和广告覆盖层冻结单局计时、棋盘移动、航道及攻击；返回后从剩余时间继续。
- 普通观察、道具目标选择、方向预览仍属于游戏进行，连击继续倒计时。
- 新手强制教学气泡暂停单局时钟，关闭后再继续。
- 玩家可以关闭声音和震动；开启“简化特效”时减少粒子和闪光，仍保留连击数、拖尾层级和命中反馈，伤害保持一致。

## 7.3 金币与长期成长边界

- MVP 初始金币为 0，所有船基础等级为 Lv.1。
- 第 n 关首次通关获得 **100＋20×(n−1)** 金币；12 关共计 2,520 金币。
- 重玩已经首通的关卡不再获得金币；不中断玩家重玩，也不增加重复刷币入口。
- 碰撞、重试和道具不花金币。MVP 没有金币购买道具、抽卡或金币兑换广告次数。
- 金币与首通标记持久保存；后续按第 3.4 节启用船型升级。MVP 不展示无法使用的升级商店按钮。
- 连击只在本局存在，不存为永久等级；同型累计数量在下一关清零。

# 8. Boss 系统

## 8.1 第一版唯一海怪

| 字段 | 设计 |
|---|---|
| bossId | TF_KRAKEN_01 |
| 名称 | 深海克拉肯 |
| 形象 | 卡通章鱼型海怪，头部／眼睛和少量触手，轮廓集中在顶部战斗区 |
| 初始血量 | 本关全部 Lv.1 船只总伤害；各关明确值见第 10 节 |
| 攻击力 | 0 |
| 攻击间隔 | 不启用 |
| 受击规则 | 固定伤害、必定命中、无无敌期、无护甲、无回血 |
| 死亡奖励 | 本关首通金币＋解锁下一关；重玩不重复给金币 |

## 8.2 三个表现阶段

| 血量比例 | 状态 | 表现变化 | 玩法变化 |
|---|---|---|---|
| 大于 70% | 挑衅 | 轻摆触手，平静表情 | 无 |
| 大于 30%、不高于 70% | 受压 | 表情更紧张，命中反馈更明显 | 无 |
| 大于 0%、不高于 30% | 濒败 | 触手降低，轮廓轻闪，水花稍加强 | 无 |

阶段由剩余血量直接决定，伤害一次跨越多个阈值时直接进入对应阶段，不强制插入多个演出。海怪触手是表现，不能拍击棋盘、改变船朝向或挡住操作。

第一版不设计 Boss 对玩家攻击、不设置我方舰队血量，也不让海怪摧毁棋盘船。后续的攻击、阶段机制和多 Boss 玩法均属于独立扩展，不隐藏进当前 MVP。

# 9. 道具系统

## 9.1 数量、入口和获取方式

三个道具均是**单局次数**，不设跨关背包。

| 道具 | toolId | 免费开局数量 | 单局库存上限 | 成功使用消耗 |
|---|---|---:|---:|---:|
| 移除船 | TF_TOOL_RESCUE | 1 | 1 | 1 |
| 洗牌 | TF_TOOL_SHUFFLE | 1 | 1 | 1 |
| 方向转换 | TF_TOOL_REVERSE | 1 | 1 | 1 |

- 第 1–2 关道具栏只做静态说明，入口锁定；第 3 关三个道具同时可用，按需短提示，不强迫玩家先消耗道具。
- 每次开始／免费重试可使用道具的关卡，免费额度重置为每种 1 次；未用完不带入下一次尝试。
- 道具只作用于仍在棋盘上的船。棋盘移动期间按钮暂时不可操作；航道或战斗运行时仍可操作静止棋盘。
- 进入目标选择模式不消耗；取消、无目标、无效目标或操作失败不消耗。效果成功落实时才扣 1。
- 使用次数和广告关系清晰显示在按钮及补充面板，不把广告伪装成普通免费按钮。

## 9.2 移除船：救援拖离

玩家点道具后选择一艘静止船，出现轻量选中轮廓，再点该船确认；点空白或取消退出选择。

救援艇／牵引光在约 0.35 秒内把目标从船阵拖离，目标不需要具备原方向的通畅路径，也不撞击途中其他船。其占位被一次性释放，然后从**距离船体中心最近的棋盘边缘**接入航道；等距时按上、右、下、左决定。

**这是一种脱困出场，不是销毁伤害来源。** 被救援船领取正常出场序号、刷新连击、融入同型舰队，并攻击一次；船型与伤害不变。救援只影响选中的一艘船，不顺带移除周围船。

## 9.3 洗牌：重新排列剩余船阵

- 使用前提示“重新排列剩余船只的位置与方向”；确认后执行。
- 只重新排列棋盘剩余实例，数量、typeId、长度、等级和伤害保持不变；可同时改变位置及上下左右朝向。
- 已经驶出的船、舰队数量、Boss 已损失血量、攻击队列和出场序号不回滚。
- 新布局必须不重叠、不越界，至少有一艘能直接驶出，且存在不再消耗道具的完整解法；至少一艘剩余船的位置或方向要发生变化。
- 只有一个剩余实例时，仍可将其朝向或位置调整为可直接驶出的有效结果；若已经不存在有效变化，不扣次数。
- 验证成功后用约 0.35 秒的缩放／淡入呈现新布局，不让船实体穿过彼此做长距离拖动。
- 无法在 0.5 秒内得到已验证结果时，保留原局面、不扣次数、提示“本次未能重排，请重试”。不能用未验证的随机结果交付给玩家。
- 洗牌本身不算出船、不生成伤害；演出期间不冻结普通连击时钟。

## 9.4 方向转换：原地掉头 180°

- 点道具后选择静止船，预览新方向，再点同船确认。
- 上↔下、左↔右；**不做 90° 转向**。
- 船占格完全不变，只对调头尾并更新船尾锚点。转向表现不受中间扫过空间限制，不推动邻船。
- 生效后船保持静止，玩家再次普通点击才移动；不能自动接着驶出而让玩家来不及观察。
- 转向不保证整局马上可解，确认前显示转向后前方阻挡轮廓，避免玩家误以为它等同于移除。
- 已出棋盘、正在移动或不存在的目标无效，不扣次数。再次使用可以转回，但要再消耗 1 次。

## 9.5 广告关系：正式规则与 MVP 状态

**正式广告补充规则已定义，真实广告 SDK 不纳入首次 MVP。**

| 情形 | 正式补充行为 |
|---|---|
| 道具库存大于 0 | 普通按钮只进入使用流程，不弹广告 |
| 库存为 0，已接入且可展示激励视频 | 玩家主动点击“看视频补充 1 次”；完整观看并获得奖励确认后，该道具 +1 |
| 主动关闭／未完成／加载失败／无广告 | 不发奖励、不扣资源，返回原棋盘 |
| 每关补充上限 | 三种道具各最多成功补充 1 次，合计最多 3 次；失败或未完成不占额度 |
| 重试当前关 | 广告补充额度使用记录不重置；补充所得的未用单局次数不继承，重试确认说明“本局道具次数将重置” |
| 离线 | 保留免费额度和免费重试，不以广告作为通关条件 |
| 暂停恢复 | 广告期间全局暂停，返回后保留连击剩余时间及当前动画进度 |

补充额度以玩家档案中的关卡 ID 记录，重复进入／重试已看过的关卡不会无限恢复；后续发布若希望增加每日额度，属于新规则，不能默默改变此表。

MVP 普通玩家界面没有伪广告或“点击立即获奖”的假视频。库存为 0 时显示已用完和免费重试入口。开发验收可通过测试入口分别模拟完成、取消、失败、重复回调，验证补充规则；测试入口不进入发布构建。第一版不放 Banner 或强制插屏，也不通过广告改变第 2 节屏幕比例。

### 内容、辨识与体验验收

- 12 个关卡都有唯一 ID、船实例／方向清单、完整无道具解法记录；无初始重叠、越界、错误方向或 HP 不匹配。
- 每关用记录的解法完整走通；洗牌后的局面使用同样的规则验证，不能只证明“有一步能走”。
- 第 3–12 关各记录至少 2 个多船中间状态作为洗牌验收样本，共至少 20 个；每个样本都须在 0.5 秒内得到有效重排并走通解法，不能用“始终返回失败、不扣次数”通过验收。
- 三种目标手机比例均满足顶部≤20%、棋盘净区≥60%、航道总面积≤5%、底部≤20%；验证刘海与底部手势区不遮挡按钮。
- 最大关在最小安全矩形下保持格边≥40；底部按钮≥48×48。没有需要滚动才能看到的船，没有热区重叠。
- 用至少 5 名未看过项目说明的测试者做首次体验。至少 4 人在 30 秒内、不经口头解释能完成一次出船，并指出“出船会攻击海怪”。
- 以最大关实际尺寸展示四种船的四向图，至少 4/5 测试者达到 90% 以上头尾／方向识别正确率；灰度下四型仍可区分。
- 玩家在 3 连击与 10 连击能感到明显表现差异，但始终看得清棋盘；关闭音效、震动及简化特效时核心信息完整。

### 稳定性与交付验收

- Android 与 iOS 各提供至少一台记录型号、系统和分辨率的真机验收记录，不以编辑器预览代替。
- 最小验收硬件规格：Android 4 GB 内存、iOS 3 GB 内存；具体测试机在开发验收前登记，性能结论只覆盖实测设备。
- 目标 60 FPS；在第 12 关、最高连击及所有船型攻击测试中，最低档验收设备不得持续低于 30 FPS 超过 1 秒。以实测记录为准，不在设计阶段声称已达到。
- 连续重玩和重试至少 30 局无崩溃、输入锁死或持续累积的船／特效对象；关卡结束后清空本局队列与临时对象。
- 断网仍可进入、完成关卡、获得首通奖励和保存；广告／归因服务失败不能卡住启动。
- 四型表现、单 Boss、三个道具、连击、结算和下一关形成完整闭环，文档中的高级功能不得被列为 MVP 必须依赖。

## Phase 1 已确认补充（2026-09-18）

- JSON 为关卡布局唯一数据源。LevelConfigSO 只保存 Unity 对 JSON 与配置资产的引用，用于加载、测试及编辑辅助，不复制船布局。
- ShipConfigSO 是船型逻辑参数唯一来源；每次加载创建独立 ShipRuntimeData，运行中不修改静态 SO。
- Boss Runtime HP 在关卡加载时按全部初始船只的 **Lv.1 伤害总和计算一次**。离场、道具及其他运行状态不触发重新计算。BossConfigSO 仅保存身份和表现，不保存固定血量。
- **TestLevel_001 教学测试关：4×6、7 艘快艇、逻辑长度 2、单船伤害 10、Boss 初始 HP 70。** 此项替代此前架构任务的 3 船／30 HP 测试规格。它是独立测试关，不自动修改第 10.3 节正式 12 关的关卡编号与配方。
- 视觉尺寸与逻辑占格分离。模型缩放、包围盒、贴图和碰撞器都不能决定占格或移动判断；逻辑只使用 Grid 数据。
- 受阻反馈枚举命名为 BlockedFeedback，舰队状态为 InFleet；后续同型展示系统使用 FleetAggregationSystem 命名，不引入船型合成。
- Phase 1 仅实现数据结构、配置加载、数据复制、合法性验证、Event 接口和 EditMode 测试；船移动、航道、战斗、UI、动画均留待后续。
