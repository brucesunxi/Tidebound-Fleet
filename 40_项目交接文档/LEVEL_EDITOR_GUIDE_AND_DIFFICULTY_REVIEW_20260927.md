# 当前关卡编辑器说明与难度改进依据

后续实施入口：[难度v2首批工具、10样关与试玩说明](DIFFICULTY_V2_IMPLEMENTATION_20260927.md)。下文保留改造前的现状审查，新增操作以实施说明为准。

日期：2026-09-27。对象：准备调整关卡编辑器、生成器和难度体系的策划／开发。

本文按当前工作树代码、100关布局及配套证明整理。**本轮只形成说明与数据复核，不修改生成规则、正式关卡、场景或玩家存档。** 下文明确区分已实现能力和改进建议；旧《关卡编辑器规划》中列出的功能不能直接视为现有功能。

## 1. 先看结论

当前工具已经能制作、检查、试玩和批量交付可通关关卡，但其主力生成路线是“找出能直接出场的船，逐步消除阻挡”。用户反馈难度不足，与以下实现和数据一致：

1. **全部100关现存证明都只含直接离场操作。** 第1关7步，其余99关各80步，没有一关必须先进行受阻前进才能清盘。
2. **挑战关的可选出口仍较多。** 第11～100关中的27个挑战关，开局实际7～11个直出目标，均值10.52；三条记录路线的前60%步骤平均仍有7.09个直出选择。
3. **难度没有按章节上升。** 第11～100关重复舒缓／常规／挑战三组出口和链深参数，后期主要轮换结构标签。
4. **结构标签的门槛区分度不足。** 新增90关全部满足“跨轴依赖≥30%”“跨区依赖≥20%”“至少3艘桥接长船”，这些最低门槛很难区分解题体验。
5. **编辑器缺少面向难度的迭代界面。** 目前有方向笔刷、文字诊断和点击试玩；尚无配方编辑面板、依赖图叠加、释放曲线图、选船属性、Undo／Redo及必要部分移动认证。

建议把下一轮目标定为：**先补难度诊断和少量对照样关，再研究必须“先挪动让路”的动态解题结构。** 单纯增加船数、提高链深或换seed，不能解除当前解题方式的上限。

## 2. 当前“编辑器”实际由三部分组成

| 部分 | 当前入口 | 已承担的职责 |
|---|---|---|
| Level Studio 手工编辑窗口 | Unity → `Tools > Tidebound > Level Studio` | 读写JSON、方向／长度笔刷、数据检查、结构指标、模型试玩、保存证明 |
| 离线关卡生产工具 | Unity工程下 `Tools/Levels/run_campaign.py` | 按C#配方生成30／100关，检查与保存布局、证明和目录，执行模型验证 |
| Campaign 接入菜单 | `Tools > Tidebound > Campaign` | 检查已认证关卡包，将30／100关目录接入竖屏场景 |

Level Studio并没有把离线生成器的全部能力做成按钮。当前调难度主要需要改C#配方和筛选逻辑，不能在窗口中拖动一个“难度滑条”完成。

### 2.1 关卡与证据放在哪里

以下路径均相对正式Unity工程 `10_开发工作区/TideboundFleet_Unity/`：

| 内容 | 位置／意义 |
|---|---|
| 第1～10关 | `Assets/Tidebound/Config/LevelPrototypes/Phase5R_TenLevelCandidates/`；沿用稳定ID `P5R_Ten_001`～`010` |
| 第11～100关 | `Assets/Tidebound/Config/Levels/Campaign/`；ID `TF_Campaign_011`～`100` |
| 布局 | `<levelId>.json`；唯一船位来源，schema v2 |
| 解法及生产证据 | `<levelId>.solution.json`；批量生成版本另包含配方、结构指标、局部诊断、三条释放曲线等 |
| 目录 | Campaign内 `manifest-30.json`／`manifest-100.json`；顺序、修订号、布局／证明SHA-256、结构及节奏标签 |
| 模型验证报告 | Campaign内 `validation-30.json`／`validation-100.json` |
| 实际游戏场景 | `Assets/Tidebound/Scenes/Phase5R_PortraitGraybox.unity`；当前完整游戏仍沿用此文件身份 |

布局保存 `schemaVersion、levelId、width、height、bossId、ships`。每船保存 `id、typeId、length、position、direction`。**position是船尾格**；从船尾沿方向占据2或3格。皮肤不决定占格，也不用于难度判断。

## 3. Level Studio 操作说明

### 3.1 打开与编辑

1. 打开菜单 `Tools > Tidebound > Level Studio`。
2. 在窗口的 `JSON` 对象框选择／拖入关卡TextAsset，再点 `Open`。仅在Project里选中文件不会自动加载。
3. 如需制作变体，先改成新的草稿Level ID，再 `Save As` 到明确的工作草稿位置，避免直接覆盖目录中的关卡。另存为本身不会自动分配新ID。
4. `Direction` 选择上下左右；`Length` 选择2或3。**这些是下一艘船的笔刷属性，不会修改已放置的船。**
5. 左键点击空格，以该格为船尾放置船；重叠或越界会被拒绝。右键点击船的任一占格，删除整艘船。修改现有船目前需要删除后重放。
6. `Width`／`Height` 调整棋盘尺寸。缩小尺寸不会自动重排或删除越界船，需重新校验和修整。

新建默认是4×6空板、`Level_New`、`TF_KRAKEN_01`，不是当前80船关的14×18规格。技术上限是24×24、160船，**不是推荐产品尺寸或已通过的触控规格**。当前窗口的Boss校验目录只有 `TF_KRAKEN_01`；这里没有Boss视觉选择器。

棋盘左下为(0,0)，x向右、y向上。每格28像素按钮；船尾格显示方向箭头和长度，其余占格显示圆点。它是逻辑格子图，不显示正式船皮肤和手机效果。

### 3.2 每个按钮实际做什么

| 按钮 | 当前行为与使用边界 |
|---|---|
| `New` | 新建空布局；没有未保存修改确认流程 |
| `Open` | 读取JSON对象框中的资源，回到编辑状态 |
| `Save`／`Save As` | 检查基础数据后原子写入初始布局；不会要求先通关，也不自动更新manifest或整包证据 |
| `Validate + Analyze` | 校验基础数据，显示占用率、方向熵、聚集度、初始出口、部分前进数、完整依赖深度及环数 |
| 百关ID下的额外校验 | Level ID匹配 `CampaignLevelPlan` 时，追加配方／结构检查及Solver结果；普通草稿ID没有同样的自动Solver入口 |
| `Local Layout Diagnostics` | 检查同向排列、4×4局部方向混合、最大空矩形、分区占用；可选择区域 |
| `Start Playtest` | 从初始布局建立模型试玩，点击船执行真实棋盘状态转换并记录有效操作 |
| `Reset Playtest` | 回到初始布局并重置本次录制；不是退出试玩 |
| `Verify Recorded Proof` | 从初始布局重放录制，区分完整清盘、尚未清盘、非法证明 |
| `Save Proof` | 仅完整清盘后保存版本化证明；不等于完成关卡包重新认证 |

关键区别：`Validate + Analyze`检查的是**初始布局**；`Local Layout Diagnostics`在试玩中检查的是**当前局面**。试玩状态栏显示剩余船、录制步数、当前出口等，不能把它与初始指标混用。

### 3.3 推荐的手工工作顺序

先保存合法的草稿布局 → `Validate + Analyze` → `Local Layout Diagnostics` → `Start Playtest` → 点击至清盘 → `Verify Recorded Proof` → `Save Proof`。

当前没有显式的“退出试玩”“上一步”按钮。需要返回编辑时，可重新 `Open` 已保存的草稿；未保存修改会丢失。也可通过保存结束试玩，但保存的是初始布局，并会清除录制器，**有价值的解法应先保存证明**。

当前没有撤销、脏状态提示或可靠的编辑会话恢复界面；重要变体使用独立草稿文件。窗口模型试玩不包含真实航道／战斗动画、移动端触控和存档验证，正式集成仍需相应回归。

### 3.4 修改现有关卡之后，为什么不能只点Save

关卡包绑定布局和证明摘要。布局一变，旧证明或manifest就可能失效。窗口的 `Save Proof` 保存通用版本化解法，**不重建批量生产侧的配方元数据、三条释放曲线和目录摘要**；直接覆盖原 `.solution.json` 不能视为完成生产修订。

当前目录校验还固定要求 `contentRevision == 1`。虽有修订字段，却没有完成供策划直接操作的内容迁移／重新认证流程。要替换正式关卡，需要明确内容版本、在途存档处理、重生成指标和证明、整包验证及场景回放。

## 5. 当前生成算法与参数

### 5.1 生成流程

空棋盘反向插船 → 得到可解骨架 → 局部重放置一艘船／改变方向 → 评分筛选 → 独立Solver → 构造解与求解器解回放 → 三种直出释放曲线 → 结构／去重 → 固定JSON与manifest。

反向插入时，每艘新放入的船必须能沿自己方向直接出场；最终倒序移除就能清盘。局部调整遇到**完整阻挡环**直接拒绝，继续保持无环依赖。求解器成功后还要求解序长度等于船数。

配方评分为0就停止局部优化。离线工具取第一个满足配方、附加结构及去重要求的候选。当前不是生成许多合格候选后再挑最有挑战的一关，也没有把全过程释放曲线加入难度硬门槛。

### 5.2 第11～100关的当前配方

| 参数 | 舒缓 Relief | 常规 Regular | 挑战 Challenge |
|---|---:|---:|---:|
| 船数／棋盘 | 80／14×18 | 80／14×18 | 80／14×18 |
| 初始直出数量 | 14～18 | 10～15 | 6～11 |
| 完整依赖最长链（节点数） | 6～10 | 8～13 | 11～18 |
| 长船数 | 4 | 6；长船桥接族8 | 6；长船桥接族8 |

通用约束：全局方向熵≥0.95，单一方向占比≤35%，相邻船同向聚集度≤0.55，不阻挡任何其他船的数量≤26，开局至少1艘能部分前进；最长近邻同向排列≤4艘，4×4有效窗口最小方向熵≥0.30、P10≥0.65，最大空矩形≤12格。

`MinPartialMoves=1`的含义是**开局至少有一艘受阻船可以前进**，不是通关至少需要一次部分移动。这是目前最容易误解的难度参数。

每十关节奏重复：舒缓、常规、常规、挑战、舒缓、常规、常规、挑战、常规、挑战。后续章节轮换结构族，但不提高上述难度参数。第1～10关有自己的旧配方；目录中的Legacy／Regular标签不能直接套用本表。

### 5.3 六种结构族的现行最低条件

| 结构族 | 检查条件 | 当前局限 |
|---|---|---|
| Flow 连续释放 | 开局直出≥14 | 主要控制舒缓节奏 |
| Layers 分层释放 | 深度≥8的船至少8艘 | 只描述依赖层数，不证明操作需要规划 |
| Crossed 多链交错 | 跨轴阻挡边≥30% | 当前所有新增关都满足 |
| KeyUnlock 关键船 | 至少一个初始直出船移除后新增≥2个出口 | 不要求该船难发现、稀缺或必须优先处理 |
| LinkedRegions 双区联动 | 跨四分区阻挡边≥20% | 统计跨区边，不直接评价玩家能否感受到联动 |
| LongBridge 长船桥接 | 至少3艘长船阻挡异轴船 | 不要求长船处在关键步骤 |

结构允许重叠是合理的；问题在于当前门槛和特征尚不足以让各族拥有明显不同的解题过程。

## 7. 为什么“很多船、长依赖链”仍可能很简单

### 7.1 当前规则下，直接离场选择缺少顺序风险

现有无环布局中，只进行直接离场时，每一步都只删除占格，不会新增阻挡；剩余依赖图仍然无环，总能继续找到出口。因此，玩家从初始局面开始，持续选择任意当前能直接出场的船，就能清盘。

这条结论限定于当前规则下的**纯直出过程**。受阻前进会占据新格，可能改变依赖或造成死局，不能推成“任意点击都安全”。

玩家一旦掌握“找一艘朝外且前面没船的船”，长链往往只是需要重复查找更多次。链深描述先后依赖，并不等于必须在脑中计划同样多步。

### 7.2 现有筛选更擅长布局质量，尚不能充分判断思考量

方向混合、同向条带和空洞门槛能改善船阵外观及空间分布，但不直接衡量首步发现、关键动作理解或错误选择的代价。当前生成器达到门槛即停，很多关停在允许出口数上限；三条曲线虽已记录，却没有用来淘汰中盘过早变松的候选。

### 7.3 游戏最有潜力的动态机制未成为必答题

“前进一段，停在阻挡前，并释放身后空间”已经是正式移动规则。现有关卡只是允许玩家这样操作，却都能绕开它、只靠直出通关。让这条机制参与必要解题过程，才可能增加超出视觉查找的思考内容；是否更好玩仍需样关验证。

## 8. 建议的改进顺序（尚未实施）

### 第一步：把诊断做成策划能使用的工具

建议先扩展现有Level Studio，增加：

- 选船属性与完整阻挡高亮：首个阻挡、后续阻挡、受阻落点、移走后解锁对象。
- 明确的编辑／试玩切换、单步撤销、Undo／Redo、未保存提醒。
- 配方编辑与检查面板：区分“开局可以部分移动”和“解法必须部分移动”。
- 开局／前段／中段／收尾的直出与部分移动曲线；显示连续低选择区间，能比较候选。
- 自动求解、纯直出剥离、证明回放作为独立按钮，对普通草稿也可用。
- 对部分移动后的状态做有界求解，分别显示“有解／已证死局／预算不足未知”。

第一版先复用已存曲线和现有Core分析，避免先发明一个无体验依据的综合难度分。

### 第二步：制作6关对照，验证A类布局还能提高多少

建议保留2关现有挑战关作对照，另外做4关实验候选。网格、船数和规则保持可比，只改变出口分布、关键释放位置及过程曲线。

可把开局2～4个出口、前60%平均3～5个出口作为**探索目标**，并加入局部结构审核。这些数字不是新生产标准，也不保证现有生成预算能实现；若代价高或只有机械单线点击，应调整目标。

筛选应覆盖多种直出策略，增加“优先最大解锁／优先最少解锁”等对照，检查是否很快进入大量自由出口。多策略结果仍是采样，不能声称覆盖全部解序。

这一步主要提升寻找出口和识别结构的挑战。**即使出口压到很少，A类仍可能成为容易看懂的长单链，不应将这一步视为完整解决方案。**

### 第三步：做必须部分前进的B类小原型

先在4～12船的局部样题中验证“先挪A让路→释放B→再处理A”这类动态关系，再评估如何嵌入完整船阵。

每个候选至少需要两类独立证据：

1. 只允许直接离场，持续剥离到无出口的固定点后仍有船，证明不存在纯离场清盘解。
2. 使用正式状态转换器，找到包含部分移动的完整无道具解，并从初始布局回放成功。

两者合起来才能说“至少必须部分移动一次”。如要声称至少需要2次／3次，需额外最小代价搜索或下界证明，不能统计某条解法里的次数就当作必要次数。

当前 `ReverseGenerationProfile` 要求至少1个初始出口、`LevelRecipe`拒绝完整环、`RecipeLevelGenerator`要求N船N步、`LevelCandidateJson.Trace`仅接受直出、`CampaignPipeline`回放也要求每步离场。这些共同形成A类生产契约。**B类需要单独的配方类型、生成／证据／曲线支持及测试，不能只把允许环的开关打开。**

现有Solver包含广度优先搜索，默认上限为20,000状态、2,000,000存储占格、5秒。小原型可复用；整80船动态关可能超预算，应返回 `LimitReached`，不能冒称无解。局部有解也不保证组合后整关有解，必须重新认证整关。

### 第四步：用体验结果重排章节并修订内容

对照记录首步有效操作时间、有效决策停顿、零位移误点、部分移动次数、重开／道具使用、实际完成时间和主观重复感。把动画等待与观察思考分开，避免用更久的机械操作冒充难度。

根据样关结果确定中后期A／B类比例和挑战节奏，再改批量配方。保留舒缓段；每关继续存在无道具、无广告、无速度要求的解。旧十关身份和进行中的挑战数据需要专门的版本兼容方案，不在原资产上直接批量覆盖。
