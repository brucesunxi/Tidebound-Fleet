## 2. 参考网页如何复用

用户提供的[Crystal Rescue政策](https://crystal-rescue.vercel.app/privacy)可借鉴公司标识、广告／订单／行为数据分项、权利请求与第三方服务说明结构。其[删除页面](https://crystal-rescue.vercel.app/delete-account)目前引导用户联系商店支持，未在页面直接提供邮箱或表单；新游戏应提供可直接使用的联系方式。

不照搬其他游戏的包名、货币、广告奖励数值、云存档、Google Play Games登录、Firebase或“仅面向13岁以上”表述。当前用户只确认AdMob、Neon自建统计和Google Play内购。Vercel用于新站是建议，不自动意味着新游戏API也部署在Vercel。

## 3. 年龄判断与建议

游戏以方向、空间关系和疏通顺序为主，伴随卡通舰船与海怪战斗；第2关起80–92艘的密集盘面和第5关起错误风险，使其比低龄启蒙游戏更复杂。**10岁左右及以上是合理的产品设计起点，但尚无9–12岁真人可用性测试证据。**

Play Console没有独立的“10+”受众选项。若产品确实同时服务儿童、青少年和成年人，候选勾选为9–12、13–15、16–17、18+；不为扩大曝光而勾选没有设计支持的年龄组。选择9–12组后也应验证9岁玩家能否理解教学、失败反馈、广告与付费。逻辑／空间解谜与Google给出的9–12岁适用方向相符。[目标受众说明](https://support.google.com/googleplay/android-developer/answer/9867159?hl=en)

目标受众是“为谁设计”，IARC内容分级是“包含什么内容”。应如实描述卡通炮击、海怪受伤表现、真钱内购和付费随机奖励（若适用），由问卷产生各地区分级；不能承诺统一为ESRB E10+，也不能因画风可爱就填写没有暴力。[内容分级说明](https://support.google.com/googleplay/android-developer/answer/9898843?hl=en)

混合受众实施建议（尚未实施）：

- 在需要区分年龄的服务启动前提供中立的年龄判断流程；儿童界定和同意年龄按发行地区核对，不以全球统一13岁代替。尽量仅保留必要年龄类别，不将完整出生日期加入行为统计。
- 儿童及年龄未知用户使用符合Families要求的广告SDK版本与广告配置，不做基于兴趣的广告或再营销，广告内容和展示形式也必须适龄。仅选AdMob或展示一个同意弹窗并不自动满足这些条件。[Families政策](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)
- 儿童及年龄未知用户不传输AAID等被禁止的标识；该限制同样覆盖自建服务器。首次启动、拒绝同意和年龄未定时均需验证。[Families数据实践](https://support.google.com/googleplay/android-developer/answer/11043825?hl=en)
- 建议默认关闭儿童及年龄未知用户的非必要、可关联到个体的行为分析；确定适用依据及必要监护人流程后再评估开放。先上传带稳定ID的明细再在后台聚合，不能称为从未采集个人数据。
- AdMob UMP处理适用的广告隐私选择；自建统计仍需独立明确目的、法律依据及必要选择。拒绝非必要统计后保持核心离线游戏可玩。[AdMob隐私流程](https://developers.google.com/admob/unity/privacy)
- 首发仅激励广告：展示前清楚说明奖励及达成条件，玩家主动选择，拒绝或提前关闭不妨碍正常使用。奖励只在满足已告知条件后发放；不把点击广告或安装被推广应用当作领取条件。[激励广告规则](https://support.google.com/admob/answer/7313578?hl=en)
- 激励广告也受儿童广告形式要求约束。对儿童或年龄未知用户，干扰正常游戏的广告必须能在5秒后关闭；需核对实际广告素材和关闭体验，不能仅因广告由玩家主动触发就忽略此项。[Families政策](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)
- 现有经济设计涉及金币抽外观；若首发真钱购买的金币可用于随机抽取，应在购买前及相关购买处清楚披露概率，并核对IARC随机物品问题。不要将有购买链路的随机奖励当作纯免费奖励。[Google Play付款政策](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)

## 4. 数据清单与实现范围

以下是实施与定稿核对表，不是已验证的数据安全答案。

|系统|拟处理数据／目的|定稿前需要确认|
|---|---|---|
|本地存档|关卡、金币、库存、收藏、偏好，提供核心游戏|哪些字段会新增上传；不要把行为统计误写成云存档|
|自建统计API＋Neon|关卡开始／完成／失败、时长、道具使用、商店及广告奖励交互；候选安装标识、版本、系统和设备类别|精确事件与字段、年龄与同意分支、日志是否包含IP、是否关联订单、用户删除定位方式|
|AdMob|广告请求、展示与交互、诊断及依版本／配置处理的网络或设备标识|实际SDK及中介伙伴、儿童设置、同意／撤回流程；按官方披露与真包复核|
|Google Play Billing|产品ID、购买凭证或令牌、订单／校验／发货／退款状态|服务端验单、访问权限、账务保留依据；不收集完整银行卡或支付密码|
|客服|用户主动提供的邮箱、消息、必要的玩家或交易参考|收件地址已确定为tideboundfleet@hotmail.com；处理人员、保留期限和回复机制待定|
|网页／API托管|可能的访问日志、IP、请求时间、错误信息|确定服务商、实际日志开关、处理地点、保留周期|

AdMob官方列有IP、产品交互、诊断与设备／账户标识等处理，具体取决于实际版本和配置。[SDK披露](https://developers.google.com/admob/unity/privacy/play-data-disclosure)

“自建后台＋Neon”仍是离开设备的数据收集；随机安装ID也可能是可关联的假名标识。仅在满足服务提供商例外条件时，某些委托处理在Data safety中不计为“共享”，但仍须披露收集并在隐私政策中说明处理方。不可填写“无收集”。[Data safety说明](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

建议架构：游戏 → HTTPS自建API → Neon；管理员通过受保护后台查看必要统计。Neon是存储层，不是自动生成行为分析的产品。数据库凭据只保存在服务端安全配置，不进入Unity客户端、仓库或公开政策页面。订单验证数据与行为统计分开授权；分析事件不附带原始购买令牌。

保存期限候选（供定稿，不是现行承诺）：非儿童可关联行为事件90天、普通技术日志30天、客服结案后12个月；儿童路径单独最小化。订单、退款和防欺诈记录根据发行地区义务另定；备份到期与删除完成时限必须按实际能力确认。只有不可合理重识别的汇总数据才能按匿名统计处理。

## 5. 没有官网如何获得政策网址

建议在公司Vercel账户建立潮汐舰队独立静态项目，以分配到的稳定生产域名承载政策，不用已有Crystal Rescue页面冒充新游戏政策。Vercel会提供以`.vercel.app`结尾的地址，无须先购买独立域名；实际名称需部署时确认。[域名说明](https://vercel.com/docs/domains/working-with-domains)

已准备页面路径：`/privacy/`（英文）、`/privacy/zh/`（中文）、`/delete-data/`（中英文数据删除说明及邮箱）、`/support/`（中英文支持联系），以及站点首页。网站本身无需连接Neon。政策页仍标有未完成事项；删除页没有冒充自动删除后台，邮件发送须由用户自行确认。

执行顺序：补齐信息并核对实现 → 生成正式HTML → 指定公司Vercel项目并授权部署 → 检查HTTPS、匿名访问、无登录／地域限制及手机可读性 → 在Play Console填真实隐私URL → 同步游戏内中英政策及入口。正式网页应是可公开阅读的普通页面，而非PDF、编辑链接、localhost或仅临时可用的预览。[隐私政策要求](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)

本次未申请域名、部署项目、购买服务或修改另一游戏网站。公司商业项目使用Vercel时应沿用适用的商业套餐；Hobby限个人非商业用途。本轮未开通或变更套餐。[Vercel使用规则](https://vercel.com/docs/limits/fair-use-guidelines)

## 7. 发行前的具体差距

1. 当前游戏内`Privacy_zh.txt`／`Privacy_en.txt`仍是离线开发期描述；在首发联网功能落地时一并更新。
2. 历史源码仍含Facebook、AppsFlyer、LevelPlay、Supersonic Wisdom和GameAnalytics等资源／入口；存在不等于全部运行，但其中Manifest provider和自动初始化需要清理或明确保留。核验最终合并Manifest、依赖树、启动流量及拒绝／儿童分支；不能只审计Tidebound脚本。详见[既有SDK核对](../20260927_GooglePlay协议/发布信息与SDK核对.md)。
3. 公司／产品和Android包名仍有旧源码配置；需另行修改并核对正式包名，本文没有调整。
4. 当前没有证据证明年龄流程、广告同意、自建统计删除、内购验单、网页公开访问已完成。文档草稿不是这些功能的验收结果。
