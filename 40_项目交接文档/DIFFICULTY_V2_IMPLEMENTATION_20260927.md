## 立即试玩

Unity菜单：`Tools → Tidebound → Difficulty v2 → Open Review Scene`，然后点击Play。

场景：`10_开发工作区/TideboundFleet_Unity/Assets/Tidebound/Scenes/DifficultyV2_Review.unity`。

顶部评审条可切换关卡、重开、单步执行证明或自动回放；右上 `−` 可折叠。手动选择偏离记录路线后，回放会停止。入口使用正式移动、航道和Boss系统，`SaveService == null`，不创建正式账户挑战、结算或存档。

建议顺序：C24→V24→R24，C38→V38→R38，再试玩P4、P8、B80-T、B80-R。先关提示比较；A组可打开原5秒提示做第二轮对照。B组评审中禁用旧“只找直出船”的提示，因为尚未适配动态关系；该限制只在独立评审入口生效。

不使用原游戏Auto搜索按钮判断B80是否有解：有限搜索可能返回Unknown。顶部 `Replay proof` 使用已经逐状态验证的完整证明。

## 新编辑器怎样用

菜单仍为 `Tools → Tidebound → Level Studio`。快捷入口 `Difficulty v2 → Inspect First Dynamic Prototype` 可直接打开P4。

1. 选择JSON后点Open；普通左键选船。勾选 `Place on empty cells` 才能在空格放船，右键删除。
2. 选船后查看路径、阻挡船、停止位置和释放格数。青色为选中占格、黄色为前方空格、绿色为部分移动后的占格、红色为最近阻挡。
3. 修改选船坐标、长度或方向后点 `Apply Selection`；非法重叠／出界不应用。`Undo Edit / Redo Edit` 回退草稿。修改初始布局会退出试玩并清除旧分析。
4. `Start Playtest` 执行真实棋盘事务；`Back / Forward` 回看历史，回退后手动点击建立新分支。它仅属于编辑器，没有给玩家加入局内Undo。
5. `Analyze A/B + shortest` 在后台分析当前状态；搜索有2秒上限，编辑／移动后旧任务结果失效。`Find feasible witness` 尝试先剥离直出船再搜索残余，只报告可行证据，失败不证明原局无解。
6. `Load saved proof` 检查相邻 `.solution.json` 的关卡、布局和每步状态指纹，加载回放与释放曲线。`Queue verified route` 把已验证路线放入时间轴。
7. 曲线显示每步剩余船R、直出E、部分前进P、E/R及新增／丢失出口。完整最短解或上下界相等时，才显示必要移动数已证明。
8. 原百关、原十关及本次已封装评审包防覆盖。修改后 `Save As` 到新草稿路径，再生成对应证明。JSON选择框切换不会把草稿悄悄写进另一个文件。

未保存草稿会标记脏状态，重新打开／新建时确认丢弃；脚本重载保存序列化草稿。完整批量生成、任意mask画刷、跨候选实时对比面板、包发布与版本迁移尚未作为UI工具完成。本批mask用于生成器和分析文件，不是棋盘墙。
