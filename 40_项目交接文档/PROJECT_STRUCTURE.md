# Tidebound Fleet 项目结构

版本：1.1；日期：2026-09-18；适用仓库：`brucesunxi/Tidebound-Fleet`。

## 根目录

```text
Tidebound-Fleet/
├── 00_远端接收区/                 外部输入隔离区；本地保留，不提交 Git
├── 10_开发工作区/
│   └── TideboundFleet_Unity/     正式 Unity 工程
├── 20_交付构建/                  APK、AAB、iOS 和测试包；不提交 Git
├── 30_设计与素材库/              正式设计源文件与已确认素材
│   ├── GameDesign/
│   ├── UI设计/
│   ├── 船只设计/
│   ├── Boss设计/
│   ├── 音效音乐/
│   ├── 外部参考/
│   └── AI生成素材/
├── 40_项目交接文档/              项目事实、基线、计划和验证证据
│   ├── API说明/
│   ├── 发布记录/
│   └── 验证记录/
├── 90_本地私密配置_不提交/       本地密钥和连接配置；不提交 Git
├── 99_垃圾存储区/                有期限的临时文件；不提交 Git
├── .env.example                 无凭据的环境变量模板
├── .gitattributes              文本换行与二进制类型规则
├── .gitignore                  生成物、私密和本地区域排除规则
├── AGENTS.md                   Codex 与开发者共同遵循的项目宪法
└── README.md                   项目入口
```

## 目录职责

### 00_远端接收区

只接收外部源码、购买资源、压缩包和参考文件。所有内容默认视为未审计，不在这里开发，不提交 Git。进入正式工程前必须完成来源、许可、版本、完整性和安全检查，并在交接文档中留下结论。

当前购买的 Unity/Cocos 项目已归档到 `00_远端接收区/已购源码与参考项目/`。Phase 0 扫描记录中的绝对路径是搬迁前的历史快照，不据此认定文件丢失。

### 10_开发工作区

唯一正式代码来源。当前 Unity 工程是 `10_开发工作区/TideboundFleet_Unity/`，包含 Assets、Packages 和 ProjectSettings。Library、Logs、UserSettings 等本机输出被根目录 `.gitignore` 排除。

Unity 工程内：

- 新业务代码与配置进入 `Assets/Tidebound/`。
- 测试进入 `Assets/Tidebound/Tests/EditMode` 或 `PlayMode`。
- 不得在 Assets 根目录创建 Test、Temp、New、Backup。
- 不修改 `00_远端接收区` 中的原始副本来完成正式功能。

### 20_交付构建

本地生成版本按 `Android/APK`、`Android/AAB`、`iOS` 和 `测试包` 分类。文件名建议包含版本、渠道和日期，例如 `TideboundFleet_0.1.0_TapTap_20260918.aab`。整个目录不进入 Git；每次对外分发的信息写入 `40_项目交接文档/发布记录/`。

### 30_设计与素材库

保存经过筛选、准备进入产品流程的源文件。`外部参考` 必须记录来源与使用边界；`AI生成素材` 必须保留提示词、生成日期、模型/服务及人工修改说明。产品规则的正式基线放在 40 目录，GameDesign 子目录用于工作稿和配套表格。

### 40_项目交接文档

这是可追溯的项目事实库：

| 文件/目录 | 用途 |
|---|---|
| `PROJECT_STRUCTURE.md` | 目录与治理规则 |
| `GAME_DESIGN.md` | 已冻结的玩法与 MVP 规则 |
| `SHIP_SKIN_COLLECTION_ECONOMY.md` | 船只皮肤、装备、抽取、金币与防刷规则 |
| `ARCHITECTURE.md` | Unity 模块、配置和数据流 |
| `DEVELOPMENT_PLAN.md` | 阶段、入口条件和交付物 |
| `PHASE5_PLUS_PLAN.md` | 高密度正式玩法从 Phase 5 起的实施顺序与阶段门槛 |
| `PHASE5_IMPLEMENTATION_SPEC.md` | Phase 5 schema、容量、输入、编辑器与验收规格 |
| `LEVEL_EDITOR_PLAN.md` | 已购项目关卡工具审计与 Tidebound Level Studio 规格 |
| `BOARD_LAYOUT_CAPACITY_PLAN.md` | 棋盘尺寸、屏幕分区、触控命中、空白率与正式船数上限 |
| `CHANGELOG.md` | 面向版本和团队的变化记录 |
| `GIT_STATUS_REPORT.md` | 当前分支、远端、忽略与敏感扫描结果 |
| `API说明/` | 无凭据的接口与环境变量说明 |
| `发布记录/` | 构建与分发记录，不存安装包 |
| `验证记录/` | 源码审计、测试结果及完整性证据 |

日志中如包含本地绝对路径，仅作为当次验证证据；新文档应优先使用仓库相对路径。

### 90_本地私密配置_不提交

保存 `.env`、数据库连接、API Key、签名相关配置和本地账号说明。目录整体忽略。仓库根目录 `.env.example` 只能保留变量名与假值。应用未来需要数据库时通过环境变量读取，禁止把完整连接串写进代码、Markdown、日志或测试夹具。

当前仅完成配置存放，不执行数据库连接、查询或迁移。

### 99_垃圾存储区

所有短期文件使用 `YYYYMMDD_用途` 前缀，例如 `20260918_UI测试.png`。包括 AI 中间图、临时截图、调试图片、一次性分析、导出日志和临时代码。目录整体不提交 Git。

每周清理流程：先搜索是否被文档、任务或测试引用；确认无引用后，清理超过 30 天的文件。不得用无确认的自动删除命令处理整个目录。

## Git 跟踪边界

应提交：正式 Unity Assets/Packages/ProjectSettings、30 目录中的正式源资产、40 目录文档、根目录治理文件。

不得提交：外部接收原件、构建产物、本地私密配置、临时文件、Unity 缓存、IDE 工程文件、APK/AAB/IPA 和系统文件。

空的正式设计分类使用 `.gitkeep` 保存目录形状；这些占位文件有明确结构用途，可在目录出现正式文件后删除。

## 数据流边界

```text
外部文件 → 00_远端接收区 → 审计/许可确认
                         ├→ 30_设计与素材库 → 人工导入 → 10_开发工作区
                         └→ 仅研究，不进入产品

10_开发工作区 → 本地构建 → 20_交付构建 → 发布记录（40）
90_本地私密配置 → 环境变量 → 未来服务适配层（值永不进入 Git）
临时产物 → 99_垃圾存储区 → 引用检查 → 每周清理
```
