# 当前奖池与十连抽生命周期审查

日期：2026-09-24。状态：源码审查、可复现离线测算与设计建议；不是新经济参数批准或运行时改动。本次不改奖池、价格、玩家存档、认可的收藏外观或支付接入。

**后续修订入口：** 最新[长期收藏方案](COLLECTION_LONG_TERM_DESIGN_20260924.md)采用7500封顶，并完整设计拖尾、船形象。用户进一步明确白船1金币、红船概率1～8、仅胜利固定约100；高品质混合平均约400含通关奖。本文此前无封顶价格、随关数线性首通及具体集齐关号保留为历史方案／旧实现审查，已被覆盖，不作为新经济结论。

## 1. 最新确认：单抽、必得未拥有完整外观

用户先提出考虑取消十连，随后明确“取消抽取的重复券”“每次抽取都会直接获取，减少不必要的复杂设计”。按此方向收敛为：

- 只保留单抽，一次消费获得一款未拥有的完整外观。
- 奖池只从当前未拥有物品中抽取；不出重复，不使用碎片合成。
- 取消十连、重复券、券兑换、紫／金／红保底及这些系统的计数展示。
- 集齐当前池后显示“已集齐”，关闭消费，仍可查看与装备。
- 船皮、拖尾、形象、场景分池，通关和分享专属不进入随机池；只开放已实现并有真实内容的池。

**最新追加：非线性价格＋品质开放门槛。**用户认为每次固定增加100过于容易，并要求金／红在达到一定关数或抽数后才有机会获得。保留单抽、不重复、无券和无保底，增加明确的抽数门槛与公开品质权重；此前剩余物品全等概率及每次加100方案不再作为当前目标。品质战斗金币上限仍是既有独立系统，本轮未改。

此前“保留十连辅助、增加共享紫色计数／稀有新款保护”的方案被本次简化取代，不再作为实施目标。下文第2～4节保留对旧实现的审计证据，第5～6节为最新设计。

**落地状态：设计已更新；运行时代码、价格、真实玩家存档尚未修改。**

### 品质概率候选

主门槛选择成功付费抽数，避免同时叠加通关数与抽数两套条件。金色第6次起可抽、红色第10次起可抽，之前概率严格为0。达到门槛是获得抽取资格，不是立即发放该品质。

基础品质权重采用白48、蓝30、紫15、金6、红1。每次先过滤未开放或该品质已全部拥有的档位，再对剩余品质权重归一化；抽中品质后，在该品质未拥有物品中等概率抽取。它们是权重，不能一直宣传为固定48%／30%／15%／6%／1%。例如三档低品质都有可抽物品时，第1～5次为约51.61%／32.26%／16.13%；某档集齐后重新计算。规则页显示本次实际品质及单款概率，主界面只展示“金色第6抽开放／红色第10抽开放”、已收集及当前价格。

**14款内容的硬约束：**默认不在池内，免费首蓝后低品质只剩7款，所以金色若晚于第8次开放就可能无可抽内容；全部非红共11款，扣首蓝后剩10款，所以红色必须最迟第11次开放才能连续抽取。本方案无需额外保底：金色必然在第6～8次首次获得，红色必然在第10～11次首次获得，是不重复与有限库存的自然结果。低品质用完后，高品质条件概率可达100%，必须如实显示。

候选3000档案模拟：首次金色在第6／7／8次分别713／648／1639人；首次红色在第10／11次分别406／2594人。此为新候选Python模型，不是生产代码或真实玩家数据。独立付费次数门槛不能保证充值或大量额外收入玩家一定到某一关才获高品质；若未来确需限制关号，应明确改成章节开放并允许池暂时无可抽内容，不暗藏额外条件。

## 2. 当前真实实现

以工作区源码为准。旧16款目录（默认＋15可抽）保留作历史回执校验；正式收藏新交易使用独立14款外观池，不能把两池相加。

| 项目 | 当前实现 |
|---|---|
| 可抽船皮 | 14款：白2／蓝3／紫3／金3／红3 |
| 全部船皮 | 31款：默认1、关卡12、分享4、抽奖14；分享渠道仍未实现 |
| 其他随机池 | 形象11、场景5有内容分配但尚不能正式抽取；拖尾5款仅为候选，正式目录还未分配这些随机来源 |
| 免费首蓝 | 通关第2关后，一个未拥有蓝皮；不增加普通抽数和保底计数 |
| 解锁 | 单抽通关第2关后；十连通关第3关后；兑换通关第4关后 |
| 单抽价 | 本随机池拥有0～3／4～7／8～11／12～14款：300／450／700／1000金币 |
| 十连价 | 起始单价×9：2700／4050／6300／9000；批内获得新款不追加费用 |
| 基础品质权重 | 白48%／蓝30%／紫15%／金6%／红1%；保护触发时另行处理 |
| 紫色保护 | 十连前9次无紫以上，第10次最低紫；连续10次单抽没有这条保护 |
| 金／红保护 | 连续19抽无金以上，第20抽最低金；连续59抽无红，第60抽红；单抽和十连共享计数 |
| 重复保护 | 连续4次重复后，下次普通低档抽取有未拥有白蓝紫时优先这些新款；不保证金红新款 |
| 重复转券 | 白10／蓝20／紫50／金120／红300 |
| 定向兑换 | 白60／蓝150／紫400／金1000／红2500券；只能兑本随机池未拥有款 |
| 保存 | 扣币、结果、收据同事务；失败重试不重抽，同请求不重复扣款 |
| 集齐 | 核心、服务、正式按钮均无14/14后停止抽取检查，仍可花9000得到十次重复；经济方案8.3／8.8只提出了关闭建议 |
| 结果表现 | 正式代码列出船名及泛化的“重复转券”说明；尚无逐项新／重复、实际转券量和本次总券量 |

白蓝紫占基础概率93%，只有8种；剩余6种金红合计7%。低档收齐后，“保底紫色”常常没有新增收藏价值。现有高品质皮肤还会提高战斗金币上限，完整经济校准需要计入装备选择。

主要源码入口在Unity工程`Assets/Tidebound/`下：`Runtime/Core/Collection/AppearanceCatalog.cs`、`AppearanceDrawEngine.cs`、`SkinCatalog.cs`中的`CollectionRules`；`Runtime/Core/Save/PlayerSaveService.AppearanceDraws.cs`、`BattleCoinRules.cs`；`Runtime/Unity/UI/VisualSamples/VisualSampleGallery.Production.cs`与`.Transactions.cs`。后两者已有正式绑定，并非只读小样。

## 3. 十连新增内容的衰减

直接编译当前Data/Core C#，调用真实`AppearanceDrawEngine`，每种情景3000个合成新档案。先免费首蓝，再连续十连；本表不兑换、不绑定关卡金币预算，以单独观察奖池。每行指第N次十连，新增不含首蓝。

| 第几次十连 | 当批平均新增 | 当批平均重复 | 当批零新增比例 | 抽后拥有中位数 |
|---:|---:|---:|---:|---:|
| 1 | 5.21款 | 4.79次 | 0% | 6/14 |
| 2 | 2.67款 | 7.33次 | 0.17% | 9/14 |
| 3 | 1.07款 | 8.93次 | 28.13% | 10/14 |
| 5 | 0.36款 | 9.64次 | 66.50% | 11/14 |
| 10 | 0.16款 | 9.84次 | 84.63% | 12/14 |

0%是有限样本结果，不表示数学保证。及时兑换会改变收藏进度，但不会让品质保底自动变成未拥有保底。

受控边界：已有13/14、仅缺一款红皮、金计数0且不临近红保底时，十连零新增样本比例96%；即使下一抽就触发红保底，仍有65%整批没有补上缺失款。保底从三款红皮中抽，已拥有红皮仍可重复。这是指定状态的实验，不是总体玩家分布。

免费首蓝后首次十连恒为2700；同组档案十次单抽平均花3891金币，中位3900。两种操作随机流不同，不能视为逐结果完全相同的对照；但实际成本差不止九折：单抽获得新款后会升档，十连整批维持旧价。这会诱导玩家憋金币，压缩早期单抽反馈。

## 6. 有限收藏周期与实施边界

14款随机船皮保留第2关免费首蓝后，最多再付费单抽13次就集齐。玩家有遗留已拥有款时，剩余次数更少。这是新规则的直接结果，不应继续设计20／60抽保底、长期重复券回收或每次十连的新款率目标。

按非线性候选，13次合计63,600金币。新玩家前两关最低累计307金币，通关第2关后领取首蓝，再花200首次付费抽取可负担；无游戏强制650金币保留。

真实100关船数、默认船最低战斗收益、可用预算全投入船皮的推演：

| 收益 | 道具预算／钱包保留 | 第6抽：金开始有概率 | 第10抽：红开始有概率 | 第13抽：完成本池 |
|---|---|---:|---:|---:|
| 当前线性首通 | 无道具、不保留余额 | 16关 | 42关 | 72关 |
| 当前线性首通 | 从第3关每关75、保留650 | 19关 | 46关 | 76关 |
| 当前线性首通 | 从第3关每关250、保留650 | 27关 | 54关 | 84关 |
| 候选首通封顶280 | 从第3关每关75、保留650 | 23关 | 90关 | 百关内未完成，仅10抽 |

因此候选和当前线性收益相匹配的方向是前期低门槛、中期积攒、后期收藏目标；不能同时悄悄启用旧首通封顶方案。每关75预算的最低收益情景，首次金色落在第19～30关，首次红色在第46～55关。预算是外生策略，不代表真人。高品质装备可增收使抽取提前；其他池消费则可能推迟，需后续联合校准。[候选规则、抽样与预算结果](验证记录/20260924_抽奖生命周期/SINGLE_DRAW_BUDGET.json)、[计算脚本](验证记录/20260924_抽奖生命周期/single_draw_budget.py)可复算。

允许玩家完成一批收藏。后续由关卡解锁外观、其他真实开放类别以及实际制作的新内容承接；不为了把14款拖满100关而引入重复、碎片、额外货币或隐性低概率。其他类的池数量和来源沿用真实目录，未开放渠道不因本次设计自动启用。

后续代码实施应独立完成：

1. 新版不重复抽取规则与逐池拥有检查；抽前集齐检查、批次入口撤除、未拥有过滤、金红抽数门槛、动态归一化概率；本池成功付费次数与非线性价格表报价同事务提交。
2. 正式UI去十连、券及保底，显示池进度和单次完整获得结果；复用已认可视觉。
3. 历史十连／券账本继续可读，不可直接改旧算法使收据验证失效。旧券余额保留在兼容数据中，已有权益的迁移／一次性处理单独确定，不擅自清零；新规则不再产券。
4. 验证未拥有过滤、最后一款、集齐后禁止扣费、重复请求、保存失败、重进结果与旧档兼容。联合复核新取得高品质的时点与金币产出，不增加新的玩法系统。

本次未运行新Unity EditMode／PlayMode，未读取或写入玩家存档。此前审计每情景3000合成档案，8个百关情景共240万关卡回合，测量的是旧抽奖实现，不能标成新版单抽验收。[旧实现结果与源码哈希](验证记录/20260924_抽奖生命周期/RESULTS.json)、[运行器](验证记录/20260924_抽奖生命周期/run_audit.py)、[C#审计源](验证记录/20260924_抽奖生命周期/DrawLifecycleAudit.cs)保留可复算。
