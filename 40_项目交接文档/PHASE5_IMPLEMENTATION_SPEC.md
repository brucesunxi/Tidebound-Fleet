# Tidebound Fleet Phase 5R 关卡体系校准规格

版本：2.1
日期：2026-09-19
状态：工程实现与自动化验收完成；产品规格冻结待真人与真机验证

## 1. 背景

原 Phase 5 已完成单基础船、schema v2、实例长度、集中 Grid 输入、JSON 写入和 Level Studio V0，自动化测试通过。这些属于有效工程基础。

原先冻结的12×18／80艘布局和随后制作的条带式灰盒不能代表目标品类。源码专项审计发现，参考项目正式关采用18×18～24×24逻辑网格、约92～124个对象和全盘四方向交错模板。Phase 5R 用于在继续开发前校准关卡体系。

## 2. 保留内容

- 单一 `TF_BASE_SHIP` 逻辑与固定10伤害。
- JSON 为关卡唯一布局源。
- position、direction、length 与视觉、皮肤分离。
- BoardModel、GridFootprint、路径扫描和移动事务。
- 集中 Grid 输入和世界坐标映射。
- Level Studio V0 的文件读写、方向笔刷和基础验证。
- TestLevel_001：4×6、7艘、Boss HP70。

## 3. 撤销内容

- 12×18正式棋盘冻结结论。
- 82艘、172占格和44空格的永久产品硬上限。
- TestLevel_002作为第2关或产品样关的资格。
- 分区同向、条带式排列和简单铺满算法。
- 未经真人验证即宣告高密度体验完成。

`TestLevel_002` 暂时保留为schema、加载、复制、输入和80对象回归夹具，命名和数据将在后续迁移中处理。

## 4. 本阶段目标

Phase 5R 只建立正确的关卡验证基础和真实交错样本，不制作正式美术、战斗、皮肤经济、广告或UI。

交付：

1. 可配置的候选棋盘规格。
2. 初始阻挡依赖图和指标报告。
3. 真实规则试玩、解法录制和回放证明。
4. 已知死局结构检测。
5. 18×18、18×22、20×20、22×22共12个交错候选样本。
6. 可运行的统一灰盒预览。
7. 真机触控与性能记录。
8. 正式网格、常用船数和上限的冻结决策。

## 5. 数据与配置调整

- schema v2 字段暂不改变。
- 棋盘尺寸限制从产品常量改为候选规格配置；仍保留合理技术上限，防止异常数据分配。
- 船数、长船比例、最低空白不作为全局常量硬编码，改由 `LevelProductionProfile` 或等价编辑器配置定义。
- 运行时 BoardValidator 只负责通用合法性；产品发布门槛由编辑器验证配置负责。
- 任何候选规格变化不得影响4×6教学关。

## 6. 依赖图

对当前棋盘每艘船调用真实前向查询：

- 有阻挡时建立 `ship → blockingShip` 边。
- 无阻挡时标记为当前出口。
- 受阻但可移动时记录可移动距离和提交后的新状态。
- 使用强连通分量标记初始环。

依赖图只是当前状态快照。船发生受阻移动后必须重新计算受影响区域，不能假设依赖永久不变。

## 7. 解法与死局

- 录制器保存 shipId 操作序列，不保存 Transform 坐标。
- 回放器从原始 JSON 新建 Session，逐步调用真实移动事务。
- 完整清盘后生成带布局哈希的解法报告。
- 小规模样本实现精确搜索测试。
- 大规模样本实现强连通分量、无出口剩余子图、重复状态和有界多策略搜索。
- 本阶段不承诺穷举100艘关卡的全部可能路径。

## 8. 样本规则

- 教程样本：4×6、7艘。
- 完整体量候选：80～110艘。
- 四方向必须散布全盘，禁止方向分区。
- 每个候选必须有一条无道具完整解法。
- 开放样本、中等依赖样本、深依赖样本各一份。
- 1×3长船只占少量关键位置，视觉固定，不参与皮肤。
- 样本只用于冻结规格，不直接进入正式关卡清单。

## 9. 测试

EditMode：

- 候选规格边界与异常尺寸。
- 依赖边和真实路径查询一致。
- 已知无环、成环、可解和死局小样本。
- 解法录制序列完整回放。
- 布局哈希变化使旧证明失效。
- 方向聚集和条带拒绝规则。

PlayMode：

- 同一 JSON 在四种候选尺寸中正确生成灰盒。
- 80、90、100、110艘的点击归属和方向显示。
- 驶出后占格、视图和数量一致。
- 不创建布局副本。

## 10. 实施结果

- 运行时通用安全上限已调整为24×24、160艘；原12×18产品常量已移出运行时合法性。
- 已实现候选生产配置、方向与空间指标、真实首阻挡依赖图、强连通分量、硬锁环、小图精确搜索、布局指纹和解法回放。
- Level Studio 已支持候选尺寸、结构分析、真实规则试玩、录制、证明验证和原子保存。
- 已建立12个固定候选JSON及对应证明，覆盖18×18／18×22／20×20／22×22和80～110艘。
- 已建立统一Unity灰盒预览，布局仍只来自JSON。
- Unity 2022.3.25f1 自动化结果为119/119 EditMode、6/6 PlayMode。

详细指标、已否决的第一轮构造和未完成的人体／设备门槛见 [Phase 5R 验证记录](验证记录/Phase5R_关卡体系校准/PHASE5R_VALIDATION.md)。

## 11. 退出条件

- 既有 Phase 1～5 自动测试继续通过，或被有说明的等价测试替代。
- 12个候选样本全部通过合法性和解法证明。
- 条带式错误样本被自动标记为不可批准。
- 至少5名首次玩家完成方向和触控测试。
- 最低目标设备完成满盘与连续移动性能测试。
- 产品负责人确认正式网格、船数范围、长船比例和第2关体量。

Phase 5R 未通过前，不进入30关量产、舰队战斗或皮肤经济实现。
