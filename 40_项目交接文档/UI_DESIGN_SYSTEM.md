# Tidebound Fleet UI Design System

版本：1.2-review
日期：2026-09-22  
适用范围：主界面、收藏／船皮肤、抽奖、补给商店、战斗 HUD、关卡、结算与奖励页面。  
基准实现：`Assets/Tidebound/Resources/TideboundUI/Prefabs/` 与 `Assets/Tidebound/Runtime/Unity/UI/Common/`。

本规范把主页定义为“玩家的船长基地”。界面应先让玩家看到自己的船，再看到开始航行，最后看到功能入口；背景只负责建立海岛氛围。它吸收《海岛船队手游_UI开发规范总文档_v1.0.md》的可执行部分，并按当前玩法、存档、Safe Area、Unity 组件边界和已购源码审计结果重新整理。参考文档中的示意数值、页面名称和外部素材不自动成为产品规则。

**2026-09-22 用户纠偏：** “船长5”并非产品需求。展示船通过通关获取，在收藏的形象分类选择，独立于局内五槽。用户本轮恢复船下名称，覆盖9月21日旧稿删除名称的要求。当前仅默认船及名称已接入，多船解锁、选择、保存待V2-D1；24船参考板不是已实现资产。

## 1. 体验原则

1. **资产优先：**玩家船是主页第一视觉。换船、装备、成长和收藏都围绕同一展示位展开。
2. **行动明确：**每个页面只有一个主行动。主页主行动固定为“开始航行 / Start Voyage”。
3. **层级稳定：**船 > 主行动 > 功能入口 > 环境；任何新资源、活动角标或运营入口不得反转该层级。
4. **规则一致：**相同作用的控件共享 Prefab、色彩、圆角、阴影、按压和禁用表现。
5. **动效有因：**动效只解释层级、状态或反馈。减弱动效模式必须关闭持续漂浮、脉冲和弹性过冲。
6. **离线可用：**资源、广告、排行或支付服务失败不能阻断进入核心游戏。

## 2. 视觉语言

关键词：Q版 3D、海洋冒险、轻松休闲、明亮卡通、宝藏探索、船长基地。

材质顺序：珍珠白主体、浅青内面、柔和厚度／投影。主页六入口去掉金边和花纹，金色主要留给主行动与资源重点；其他组件可保留少量木质标题牌与绳结装饰。木材只用于标题和叙事性装饰，不能让同级按钮出现多套材质。

体积由四层建立：

1. 外轮廓或金色包边；
2. 珍珠白／金色主面；
3. 顶部柔和高光；
4. 向下 4–8 px 的海蓝色厚度与投影。

禁止使用扁平网页卡片、纯描边按钮、写实金属、霓虹赛博光、过量渐变和不同组件各自定义的圆角。

## 3. 颜色系统

所有功能色只从五个基础色派生；代码唯一入口为 `HarborDesignTokens`。

| Token | Hex | 用途 |
|---|---:|---|
| Ocean Blue | `#169BD5` | 主品牌色、选中、信息、海洋阴影 |
| Pearl White | `#FFFFFF` | 面板与按钮主体、反白文字 |
| Gold | `#FFC928` | 主行动、奖励、稀有与重点描边 |
| Emerald Green | `#39C98A` | 成长、完成、可领取、正向状态 |
| Coral Red | `#FF6655` | 风险、关闭、失败、破坏性操作 |

允许通过透明度或同色明度得到 `OceanShadow`、`OceanSoft`、`PearlWarm`、`GoldDark` 和 `Disabled`，不得新增第六个语义色。正文深色使用 Ocean Blue 的深色派生值；半透明遮罩使用 Ocean Blue 深色派生值。

对比要求：正文和底色达到移动端可读对比；Gold 不直接承载小字号白字；禁用状态同时降低饱和与透明度，不能只靠颜色区分。

## 4. 尺寸、圆角与阴影

设计基准宽度为 390 dp，运行时按宽度缩放并在 Safe Area 内布局。最小触控区 48×48 dp。

| Token | 值 | 用途 |
|---|---:|---|
| Radius S | 12 | 标签、角标、小状态 |
| Radius M | 20 | 通用按钮、资源条 |
| Radius L | 28 | 主按钮、主要面板 |
| Shadow Common | 5 px | 通用按钮厚度 |
| Shadow Main | 8 px | 主行动厚度 |
| Space Unit | 4 dp | 所有间距使用 4 的倍数 |

相同层级只能使用同一阴影方向。默认阴影向下，颜色为 `OceanShadow`；浮层可增加低透明环境阴影，但不能更换成黑色硬阴影。

## 5. 字体与文案

首页展示字体由 `HarborUI.DisplayFont` 统一选择：中文使用 Resource Han Rounded CN Bold，英文使用 Lilita One，使用字体文件的原生字重（中文 Bold，英文 Regular；Unity 不再叠加伪粗体），数字随当前语言字体。`HarborText.UseDisplayFont` 在切换语言及重新启用时保持这一路径。长说明与弹窗正文使用 `HarborUI.Font` 的 Noto Sans CJK SC。三者均为项目内资源，不依赖系统字体；新增两款展示字体附 OFL 1.1 许可证。禁止在单个页面直接指定系统字体。

| 层级 | 基准字号 | 规则 |
|---|---:|---|
| 页面标题 | 28–34 | Bold，一行 |
| 主行动 | 26–30 | Bold，动词优先 |
| 卡片标题 | 18–22 | Bold |
| 正文 | 14–18 | Regular／Medium |
| 状态／说明 | 11–14 | Medium，不能成为唯一状态线索 |

文案优先写玩家行为：`Start Voyage`、`Equip`、`Claim`。主页英文标签单行；中文以语言设置独占显示，不在同一按钮堆双语。文本膨胀测试覆盖英文 1.35 倍和中文长状态。

## 6. 主页布局合同

`UI_MainMenu` 采用竖屏单 Canvas，层级固定为：

```text
UI_MainMenu
├── Background
├── BackgroundFocusOverlay
├── TopHUD
├── PlayerShipView
├── LeftMenu
├── RightMenu
├── MainActionButton
└── Notice
```

- 顶部约 10%：设置、金币；取消“船长N”或玩家等级。
- 中部约 60%：玩家选择的主页展示船；下方显示该船名称，与通关关数、玩家昵称无关。名称不随船摇摆。默认展示为“海风旗舰 / Sea Breeze”。
- 左侧：Collection、Skin Draw、Supplies，表示成长与资产。
- 右侧：Daily Gift、Invite、Rankings，预留每日奖励、邀请有礼、排行榜。未实现入口不可点击，不加“可用／待开放／Soon”文字。
- 底部：唯一主行动，不覆盖码头视觉锚点；船名位于船下、主按钮上方；临时消息位于主按钮下方。
- 左右入口每侧最多 3 个。新增入口须替换、合并或进入二级页面，不能继续纵向堆叠。

背景在运行时统一使用饱和度 `0.85` 与轻度采样模糊，源图保持不变。顶部和左右 UI 区域叠加低透明聚焦暗层。禁止在 Photoshop 中为每个页面另存不同暗化背景。

## 7. 玩家船展示合同

`UI_Ship_Display` 是资产展示容器，不读取 Transform、Renderer 或 Collider 决定逻辑占格。

必须包含：

- 船体轻微上下浮动；
- 接触水线与局部水波；
- 柔和倒影或反光；
- 船长轮舵、旗帜、探照／科技炮台、宝箱或装备挂点中的至少三类；
- 减弱动效与页面失焦时冻结持续动画。
- 展示相机固定方形 RenderTexture 纵横比，初始化时按展示模型顶点计算取景边界并保留4%余量；这只决定镜头，不参与逻辑 Grid。
- 倒影使用同一 RenderTexture 的独立低透明材质，压缩翻转后置于船底水线以下；其时间参数与船的摆动同源，页面销毁时释放材质。

船体点击后进入收藏／装备流程时，旧 attempt 的逻辑身份与收益不回写。主页展示可以切换外观，但核心玩法规则保持不变。

## 8. 组件目录与职责

### `UI_Button_Common`

通用入口和弹窗次级按钮。固定子节点：`Face/IconSlot/Label/Status`。主页入口84×92，图标按真实可见区域取景并保持比例，在72×61区域居中；底部只留一行10–12字号标题。Status保留兼容节点但停用，不作为视觉元素。按钮根节点承担点击和完整触区，按压只移动 `Face`，不能移动根节点或缩小触区。

状态：Default、Pressed、Selected、Disabled、Locked、Loading。Pressed 为 2–4 px 下沉和高光收束；Selected 使用 Ocean Blue 派生底色与 Gold 重点；Disabled 不响应导航；Locked 同时显示锁图标和原因。

### `UI_Button_Main`

页面唯一主行动。固定子节点：`VoyageGlow`、`Face/Label`、`Face/SubLabel`、`Face/WheelAccent`。主页使用独立 Gold 透明皮肤、船舵与船锚徽章、金色高光与低幅脉冲。文字位于金色内面，不能落到下侧厚底或海浪装饰上。按压反馈必须在 100 ms 内开始。

### `UI_HUD_Resource`

资源胶囊。图标、数值和可选加号位置固定；数字变化使用短促跳变或滚动，账本提交先于动画。资源不足不能只弹 Toast，应提供可理解的获取入口。

### `UI_Ship_Display`

只负责展示与动画，不承担收藏、购买或关卡逻辑。数据通过初始化接口传入。

### 后续必建组件

- `UI_Popup_Base`：遮罩、面板、标题牌、关闭、内容槽、底部行动槽；
- `UI_Tab_Common`：默认／选中／角标；
- `UI_Item_Card`：图标、品质、数量、锁定、已装备；
- `UI_Toast`：短状态反馈；
- `UI_Reward_Reveal`：单奖励与多奖励展示。

页面脚本不得复制组件内部的阴影、圆角或按压实现。

## 9. 弹窗与页面框架

层级从低到高：Background、Page UI、Popup、Dialog、System、Toast、Guide。单例页面可保持实例；高频列表和奖励卡使用对象池；关闭时解除临时监听并清除旧会话标识。

弹窗开场基准为 220–320 ms：`0.92 → 1.03 → 1.00`，遮罩同时淡入。关闭为 160–220 ms：`1.00 → 0.96` 并淡出。减弱动效模式只保留 120–160 ms 淡入淡出。

外部点击是否关闭必须逐页面声明；购买确认、奖励领取和可能丢失编辑状态的页面禁止点击遮罩关闭。关闭后焦点回到打开该页面的按钮。

## 10. 页面应用规则

- **船皮肤／收藏：**船是第一视觉；卡片展示拥有、未拥有、已装备和获取途径；五槽只属于皮肤。
- **抽奖：**奖励预览和保底是第一视觉；价格、次数和概率说明在确认前可见；重复转券规则保持明确。
- **商店：**商品内容和价格是第一视觉；金币、广告、真钱入口使用不同语义标签但共享组件骨架。
- **战斗 HUD：**船、海怪和可操作信息优先；不复制主页侧边入口；HUD 避让安全区和棋盘触区。
- **关卡页：**只显示解谜、道具、Boss 与必要导航；长期运营入口返回基地处理。
- **奖励／结算：**奖励先于统计；入账成功后再播放飞币或揭示；重试不得重复结算。

## 11. 动效参数

| 动效 | 幅度 | 周期／时长 |
|---|---:|---:|
| 船浮动 | 3–6 dp | 2.2–3.2 s |
| 图标漂浮 | 2–4 dp | 1.8–2.8 s |
| 主按钮辉光 | Alpha 0.08–0.18 | 1.2–1.8 s |
| 按压下沉 | 2–4 dp | 80–120 ms |
| 弹窗开场 | 0.92→1.03→1.00 | 220–320 ms |
| Toast | 淡入／停留／淡出 | 120/1200/180 ms |

持续动画使用 unscaled time，暂停和后台恢复后不得跳相。动效不能改变 Button 根节点触区或业务完成时机。

## 12. Unity 实现规则

正式路径：

```text
Assets/Tidebound/
├── Resources/TideboundUI/Prefabs/
├── Runtime/Unity/UI/Common/
├── Runtime/Unity/LevelDesign/
├── Editor/UI/
└── Tests/{EditMode,PlayMode}/
```

- 颜色、圆角、阴影和最小触区从 `HarborDesignTokens` 读取。
- 共用组件必须 Prefab 化；运行时用 `HarborUI.Prefab` 创建。
- Prefab 由 `Tidebound/UI/Rebuild Design System Prefabs` 确定性生成。
- 页面控制器只负责装配、数据绑定和导航；视觉状态留在组件。
- Safe Area 和横纵比逻辑集中处理，覆盖 20:9、19.5:9、16:9 竖屏。
- 所有按钮支持 EventSystem 导航；关闭弹窗恢复焦点。
- 视觉尺寸与逻辑 Grid 占格严格分离。

## 13. 资源生产与命名

命名：

```text
UI_<Page>_<Role>
UI_Button_<Variant>
UI_HUD_<Role>
Icon_<Function>_v<Major>
FX_UI_<Effect>
```

本轮皮肤通过 `HarborReliefImage` 的九宫格网格绘制：`SliceUV` 指定左／下／右／上源纹理不可拉伸占比，`SliceSize` 指定目标画布单位边框；小触区按比例缩小固定边框，不能挤出负中心尺寸。设置入口采用 56 dp 专用边框；文本型次级操作采用横向胶囊皮肤，避免拉长竖向首页卡片。原 PNG 保持不变。资源源稿与提示词见 `30_设计与素材库/UI设计/20260922_主页视觉皮肤/`。

图标统一正视或轻俯视的 Q 版 3D 角度，主体占图框 70–82%，使用透明背景和一致光源。九宫格边框的不可拉伸角区必须记录；Sprite Atlas、纹理压缩和 Mipmap 设置在目标机验证后冻结。

任何外部购买素材进入正式库前必须记录来源、许可、修改方式、目标文件与哈希。授权不完整时只能研究结构和行为。

## 14. 质量门槛

每次新增或修改页面必须完成：

1. 390×844、360×800 与至少一个 16:9 竖屏截图；
2. Safe Area、遮挡、文本膨胀、48 dp 触区检查；
3. Default／Pressed／Disabled／Selected／Loading 状态检查；
4. 弹窗输入隔离、焦点返回、重复点击和失败重试检查；
5. 减弱动效、暂停、后台恢复检查；
6. EditMode 编译与相应 PlayMode 流程测试；
7. 性能检查：主页稳定帧无持续 GC 分配；低端机过度绘制与材质数记录（移动端验收仍待进行，不用 Editor 截图代替）；
8. 运行截图和真实测试结果写入 `40_项目交接文档/验证记录/`。

下列情况不得标记完成：只交合成效果图；运行时未使用 Prefab；视觉状态由业务脚本各自绘制；未验证小屏；借用资产却没有授权记录；把未运行测试写成通过。

## 15. 变更治理

Design System 变更分三类：

- Patch：不影响布局合同的颜色微调、Bug 修复；
- Minor：增加兼容组件或状态；
- Major：修改颜色语义、组件树或页面层级。

Major 变更需同步更新 Prefab Builder、运行时组件、设计文档、截图基线和相关测试。任何页面的局部需求若会破坏全局一致性，应先补充通用 Variant，再由页面引用。

## 16. C2 弹窗与结算补充（2026-09-22）

新增 UI_Popup、UI_Tab、UI_ItemCard 三个 prefab。主页六图标仍保持图大字小；弹窗使用独立奶油金边与木牌船舵标题，关闭红圆按钮最小48单位。标题图约3:1固定比例，内容可滚动，底部分类／导航不随正文滚动。新字体与文字不烘焙进图片。

收藏皮肤卡保持真实16款目录身份和五槽业务，当前统一示意图不代表16款正式美术均已生产。补给救援／洗牌／转向采用独立RGBA图，价格来自现有目录。抽奖展示图与标准皮肤预览分开，金／红保底读取实际计数。

结算轻动效遵守减少动效与焦点；分享预览覆盖并阻断底部入口。预告为未来外观分类，不用虚构具体奖励或排行榜数据。所有验收画面来自 Unity Editor 2022.3.25f1，移动端性能与触控仍待验收。
