## 3. 自动帮助必须区分的状态

| 当前盘面 | 5秒自动高亮 | 自动死局弹窗 | 是否有死局部分结算资格 |
|---|---|---|---|
| 至少一艘能沿自身方向直接驶出 | 是，选其中一艘 | 否 | 否 |
| 无直出船，但至少一艘能部分前进 | 否 | 否 | 否 |
| 完全无船能前进或驶出，且盘面非空、没有未完成移动意图 | 否 | 是 | 按已有严格死局、命中金币与每日前10次重开规则计算 |
| Solver判无完整解，但仍有船能移动 | 仅在存在直出船时提示 | 不因该求解结果自动弹“完全死局” | 否 |
| Solver预算耗尽／未知 | 仍按实际直出查询决定 | 不因Unknown弹窗 | 不能据此结算 |
| 棋盘空、航道或攻击未完成 | 否 | 否 | 等待原战斗胜利屏障 |

### 3.1 5秒直出提示：明确规则与建议细节

已明确：游戏阶段连续5秒无操作；仅高亮一艘当前可直接驶出的船；无直出目标时不显示，不改成部分移动建议。提示免费、不自动移动、不占三道具库存或每局5次额度。

工程上复用`BoardModel.QueryForwardPath`及现有合法离场判定；不能只看`TravelDistance > 0`，因为这也包含部分前进。现有`ShowHint()`会完整求解并可能推荐部分前进，因此不能直接定时调用它充当本功能。手动完整解法提示是另一功能，后续命名／入口要区分。

建议交互参数（待灰盒验证，5秒触发本身来自用户要求）：

- 计时只在前台、可操作的局内状态进行；入场、暂停、结算、弹层、反转选船、自动演示时停止并清除高亮。返回可操作状态后重新计满5秒。
- 点击船、点空白、操作HUD及按住／拖动等实际用户输入都重新计时，避免用户正在操作却被提示；自主航道／炮击效果不当作用户操作。
- 船移动或道具修改盘面后，撤销旧提示并在稳定新盘面重新计时；目标高亮前再校验当前位置与直出资格。
- 多目标时使用稳定顺序选一艘；不宣称“最优船”，不按稀有度／收益推荐。
- 单船方向标或轮廓做两次柔和脉冲（合计约1～1.5秒为候选）；无需压暗全盘或弹文字卡。用户触屏立即停止。
- 同一盘面一次闲置周期只提示一次，不每5秒换船闪烁；有新操作／盘面变化后才重新武装。减少动态设置下用静态轮廓；设置中可关闭自动帮助。
- 按盘面版本缓存候选，不每帧运行Solver；后台期间不累计到前台瞬间触发。

### 3.2 完全死局弹窗：帮助，而不是强制消费

复用现有`BoardProgressMonitor.NoMoves`与`SavedGameRuntime.IsTerminalDeadlock`语义。`NeedsRescue`同时包括`Unsolvable`，不能直接拿它作为“完全无船可动”的自动弹窗条件。

建议模板：标题“暂时没有船能移动”；正文说明可以使用道具或重新挑战。显示三道具库存与本次剩余额度，只把当前确实可执行的入口设为可用；不承诺随机救援、反转或洗牌一定能最终解开所有死局。

- 有库存且有额度：选择道具；救援／洗牌沿用现有直接执行，反转关闭弹层后进入选船。
- 没库存且有额度：进入已有金币商店。购买仍不自动使用，商店关闭后回到明确的继续操作状态。
- 已用满5次：明确“本次挑战道具次数已用完”；重开为主要可用操作；不能把购买包装成当前局恢复使用资格。
- 重开展示真实可结算的已命中金币；额度耗尽或无可结算金币时显示0，按原规则执行。关闭／继续观察也可选，打开弹窗本身不终结attempt。
- 以attempt与盘面状态去重：关闭后同一盘面不反复弹；道具造成新盘面后再次完全死局才可再次提醒。无需仅为这项提示新增账户经济回执。
- 棋盘已稳定但尚有航道／攻击时，建议先让短暂反馈收尾再呈现，并在弹出前重查；用户主动打开其他界面则取消排队提示。最终金额始终由原结算服务计算。
- 弹层打开即锁棋盘并取得暂停所有权；进入商店、返回、选船、重开全过程不能误恢复用户原本暂停的游戏。

## 4. 3D视觉方向与现有工程如何衔接

本轮明确采用的方向是：**真实低复杂度3D船体＋正交相机＋低成本接触阴影＋2D HUD，顶部战斗事件驱动。** 先做技术与可读性原型，尚不生成16款正式美术。

当前`PortraitPuzzleGraybox`已经有正交棋盘相机、`GridWorldMapper`和独立HUD，但船体仍是World Space Canvas的Image。因此不是替换一张图片即可完成，也不需要推翻Grid、移动、Solver和存档。

最小切片：标准船原型1个、长船原型1个、5种临时材质，共用清晰船头、方向标、阴影；通过视图适配接口接现有移动、航道、舰队和提示状态。原UI灰盒保留作回归参照，避免长期维护两套玩法逻辑。

逻辑位置由既有映射与移动控制；浮动、后坐、命中只改视觉子层。当前Grid映射在XY平面，不能照抄指导文档中的“Y轴上下浮动”让船在屏幕上错格；高度轴须按实际世界映射定义。点击仍落到逻辑平面和整数格，不能用皮肤Mesh Bounds推断船占格。

正交投影本身不会消除斜视造成的平面压缩。指导文档的55°～70°俯角不作为冻结参数；第一版保持正俯视／接近正俯视的清晰投影，用船体厚度、甲板、法线明暗和Blob阴影形成体积。需要倾斜时，必须重新检查投影后的格形、触点与遮挡，不能直接旋转现有相机就算完成。

先用现有渲染管线验证；不因设计文档出现VFX Graph／GPU Instancing等词就升级管线或导入框架。共享材质、阴影和特效数量控制是候选实现策略，实际批次、透明叠加和设备性能要测量。30／60 FPS与粒子上限属于目标，不是已有证据。

### 4.1 顶部安静与80船连续攻击的矛盾

单次炮击很短，不代表80次叠加就安静。表现层需要统一分配反馈预算：

- 没有出船时：低幅待机，不主动发射；棋盘上仍可继续思考。
- 普通入舰／命中：对应席位和Boss局部反馈，不让整块HUD反复放大。
- 高频连击：每船一次AttackToken、固定10伤害和真实命中照常完成；合并伤害数字、限制大闪光／音效／强震的频率，让高密度反馈仍可读。
- 最后一击：顶部短收尾后显示结算。局部相机／舞台可以动，棋盘投影与触区保持稳定。
- 动效订阅现有权威时点；不为凑文档里的0.45～0.65秒重新定义伤害、队列或收益时序。

## 5. 胜利结算与真实的下一目标

现有持久模式在胜利落盘后约1.2秒自动切下一关，应规划为“已结算 → 展示结果 → 玩家继续”。进度仍在胜利时可靠保存，进入下一关的呈现时机与推进账本分开。

推荐首版结算只包含：

1. 本关成功反馈，标准船／旗舰代表与顶部短收尾。
2. 首通金币、战斗金币、合计；读取已落盘的同一胜利凭证，动画跳过／重播不重复入账。
3. 一条主要目标轨道：优先海域章节的真实通关进度，如“6/10，距下一海域还有4关”。示例内容是拟议UI，未发布章节不能显示成已可玩。
4. 一条次要收藏提示：已收集X/16，或玩家所选未拥有皮肤还差多少收藏券；第2关时替换为已确定的免费蓝皮首抽入口。
5. 主按钮“下一关”；在本轮已发布最后一关改为“已完成当前内容”，不能进入不存在的第11关。

无需为这条进度另造可消费星币。首次通关数直接驱动章节位置；皮肤已有金币、收藏券与保底，继续复用。概率抽取不能写成“再过两关必得某皮肤”，可表达“距一次抽取还差X金币”；确定性定向兑换才展示准确的目标差距。

进度表现建议：先展示本次变化，再轻移轨道露出下一节点；当前点、下一目标和一个远期节点即可。不使用没有来源的“超越XX%玩家”、虚构头像或假排名。真实榜单仍在既有后续阶段，离线时先显示个人章节／收藏。

恢复规则需与I5-C一起考虑：已结算但还没点继续的结果页可以恢复，不能重发金币、首次蓝皮或章节奖励。新关皮肤与收益应在玩家看完结算、处理首抽／装备并正式开局时锁定，避免提前创建第3关导致免费首抽装备要到第4关才生效。

若后续加入章节实物奖励／收藏券，必须使用既有唯一领取回执并纳入经济模拟；本轮不擅自增加奖励来源。真实广告未接入前，结算翻倍隐藏或明确不可用，不做本地假发货。
